# Chain Prompts — AI Agent Cybersecurity Skills Pack v1.0

4 條完整安全審計流程鏈：將多個技能串接成端到端工作流程

---

## 🔗 Chain 1：PR 安全審查流程（10 分鐘）

**適用時機：** 每次 Pull Request 前的安全快速審查

**Step 1 — 攻擊面識別**
```
請快速掃描這次 PR 的改動（[git diff 或檔案清單]），識別：
1. 新增的外部輸入點（API endpoint / 表單 / 文件上傳）
2. 新增的外部依賴（npm install / pip install）
3. 修改的認證/授權邏輯
4. 修改的資料庫查詢
輸出：變更摘要 + 需要深入審查的文件清單
```

**Step 2 — 高風險程式碼掃描**
```
請深入審查以下文件（上一步識別出的高風險文件）：
[文件清單]

執行：
1. SQL/NoSQL injection 風險掃描
2. 硬編碼密鑰掃描
3. 不安全函式使用（eval/exec/pickle）
4. 輸入驗證缺失
```

**Step 3 — 授權邊界驗證**
```
請驗證新增的 API 端點是否有正確的授權檢查：
[端點程式碼]
1. 是否有認證保護（非公開端點）
2. 是否有資源所有權驗證（防 IDOR）
3. 是否有角色權限驗證
```

**Step 4 — 生成安全審查報告**
```
請根據以上掃描結果，生成 PR 安全審查報告：
- 🔴 阻斷合併的問題（附修復程式碼）
- 🟡 建議修復的問題（不阻斷，但需追蹤）
- ✅ 安全通過的項目
```

## 🔗 Chain 2：新功能上線前安全審計（30 分鐘）

**適用時機：** 新功能 / 新服務上線前的完整安全評審

**Step 1 — 威脅建模**
```
請對以下新功能執行 STRIDE 威脅分析：
[功能描述]
輸出：威脅清單（按 DREAD 評分排序）+ 前 5 大威脅的緩解措施
```

**Step 2 — 程式碼安全審計**
```
請對以下程式碼執行 OWASP Top 10 安全審計：
[程式碼或檔案路徑]
逐條評估 A01-A10，標記存在風險的項目
```

**Step 3 — 配置安全審查**
```
請審查以下部署配置的安全性：
[Docker Compose / K8s YAML / Terraform / 環境變數]
找出：明文密鑰、過度寬泛的 Security Group、缺少加密、過高的 IAM 權限
```

**Step 4 — 生成上線前 Checklist**
```
請根據以上審計結果，生成上線前必須完成的安全 Checklist：
- 🔴 必須修復（不修不能上線）
- 🟡 建議修復（上線後 2 週內）
- 📋 需要監控的指標
```

## 🔗 Chain 3：事件回應流程（緊急）

**適用時機：** 發生資安事件時的快速回應

**Step 1 — 初始評估**
```
資安事件發生！請協助快速評估：
事件描述：[描述]
可用日誌：[日誌片段]

立即識別：
1. 攻擊類型（injection / 帳號接管 / 供應鏈 / DDoS）
2. 影響範圍（哪些系統 / 資料 / 用戶）
3. 攻擊是否仍在進行
4. 立即遏制措施（封鎖 IP / 撤銷憑證 / 停用服務）
```

**Step 2 — 根本原因分析**
```
請協助分析此事件的根本原因：
[日誌 / 程式碼 / 配置]

輸出：
1. 攻擊時間軸重建
2. 漏洞位置（檔案 + 行號）
3. 攻擊者利用路徑
4. 對應的 MITRE ATT&CK Technique
```

**Step 3 — 修復方案生成**
```
請根據根本原因，生成緊急修復方案：
1. 立即修復（1 小時內）：暫時緩解措施
2. 短期修復（24 小時）：程式碼/配置修復
3. 長期修復（1 週）：系統性防禦改善
附：每個修復的具體程式碼 / 配置
```

**Step 4 — 事後報告草稿**
```
請根據以上信息，生成資安事件報告草稿（適合給管理層）：
- 事件摘要（非技術語言）
- 影響評估（用戶 / 資料 / 業務）
- 已採取措施
- 預防再次發生的計畫
```

## 🔗 Chain 4：供應鏈安全加固（週期性）

**適用時機：** 每月或每季執行的供應鏈安全審查

**Step 1 — 依賴項全面掃描**
```
請對 [專案] 執行完整的供應鏈安全掃描：
1. 識別所有直接 + 傳遞依賴
2. 標記 CVE 漏洞（CVSS >= 7.0）
3. 標記無人維護套件
4. 標記疑似 typosquatting 套件
5. 標記授權風險（GPL 在商業專案）
```

**Step 2 — CI/CD 安全配置審查**
```
請審查 [CI/CD 配置] 的供應鏈安全：
1. 第三方 Action 是否固定 commit SHA
2. Build 過程是否可被污染
3. Artifact 是否有簽名驗證
4. Secret 是否安全傳遞
```

**Step 3 — 映像安全掃描**
```
請協助設計容器映像安全掃描流程：
[Dockerfile + K8s 配置]
1. 基礎映像 CVE 掃描配置（Trivy / Grype）
2. 映像簽名配置（Cosign）
3. Admission Controller 驗證策略
```

**Step 4 — 供應鏈加固計畫**
```
請根據以上掃描結果，生成供應鏈安全加固計畫：
- 本月必做（高風險）
- 下月計畫（中風險）
- 長期策略（SLSA Level 2+ 目標）
附：每個步驟的具體工具和配置
```
