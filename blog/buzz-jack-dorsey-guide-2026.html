Buzz 完整教學 2026：Jack Dorsey 開源 Slack + GitHub 替代方案，ACP 整合 Claude Code / Codex

Buzz 是什麼？為什麼開發者社群在意

Buzz 是一套開源的團隊協作平台，定位介於 Slack（即時通訊）與 GitHub（程式碼協作）之間。它不是又一個聊天室 clone，核心賣點有三個：

  • 去中心化身份：採用 Nostr 協議做底層通訊，帳號不掛在單一公司伺服器上，你的訊息資料理論上可以搬到任何相容的 relay。
  • 原生 AI Agent 整合：透過 ACP 標準，聊天室裡可以直接 @ 一個 AI Agent，讓它讀 repo、跑測試、開 PR，回報結果直接留在對話串裡。
  • 開源自架：程式碼完全公開，可以部署在自己的 VM 上，沒有訊息數量限制、沒有座位數收費模式。

對台灣的中小型開發團隊來說，這個組合特別有吸引力：不用同時付 Slack 訂閱費 + GitHub 團隊方案，還能把 AI Agent 直接嵌進日常溝通流程，而不是切來切去在瀏覽器分頁之間。

💡 時機點：Buzz 發布時間正好卡在 Claude Code、Codex、Cursor 等 coding agent 高速普及的窗口。Jack Dorsey 本人在 Block 內部已經用類似架構做內部工具測試超過一年，這次算是正式對外開源。

底層架構：為什麼選 Nostr 協議

Nostr（Notes and Other Stuff Transmitted by Relays）是一個近年在去中心化社群（尤其是比特幣圈）快速成長的開放協議，Jack Dorsey 本人是長期支持者。它的設計哲學很簡單：

特性傳統 SaaS（Slack）Nostr（Buzz）
身份系統Email + 密碼，公司控管公私鑰對，使用者自己保管
資料儲存單一供應商伺服器可分散在多個 relay
搬遷成本幾乎無法搬走歷史訊息理論上可換 relay 保留身份
審查風險公司可單方面停權帳號抗審查性較高

對一般團隊來說，最實際的影響是：你的公私鑰就是你的帳號，弄丟私鑰基本上等於帳號報廢，這點跟傳統「忘記密碼、按重設連結」的體驗完全不同，是團隊導入前必須先教育成員的重點。

ACP 整合：讓 Claude Code / Codex 直接進聊天室

這才是 Buzz 真正讓開發者興奮的地方。ACP（Agent Client Protocol）是近期由多家 AI 工具供應商共同推動的標準協議，目的是讓不同的 coding agent（Claude Code、Codex、Goose 等）能用同一套介面被外部應用程式呼叫，而不用各自寫一套整合。

在 Buzz 裡，設定完 ACP 連接後，工作流程大概是這樣：

# 頻道裡直接呼叫 agent
@claude-code 幫我看一下 #1234 這個 issue，開一個修復的 PR

# agent 會回覆進度，並把結果貼回同一個 thread
[Claude Code] 正在分析 issue #1234...
[Claude Code] 已建立分支 fix/issue-1234，PR #1235 已開啟，等待審核。

重點是整個過程留在聊天記錄裡，團隊成員不需要切到 GitHub 或 terminal 去看 agent 到底做了什麼，審核 PR 前也能直接在同一串對話裡問 agent「你為什麼這樣改」。

目前支援的 Agent

  • Claude Code（Anthropic）— 目前整合度最完整
  • Codex CLI（OpenAI）— 支援基本任務派工
  • Goose（Block 自家開源 agent）— 因為同屬 Dorsey 陣營，整合最深

安裝與自架教學

以下是最基本的自架流程（以 Docker Compose 方式部署為例，適合先在測試環境跑起來）：

# 1. Clone 專案
git clone https://github.com/jack/buzz.git
cd buzz

# 2. 複製環境變數範本
cp .env.example .env
# 編輯 .env，設定 Nostr relay 位址、資料庫連線字串

# 3. 用 Docker Compose 啟動
docker compose up -d

# 4. 開啟瀏覽器造訪 http://your-server-ip:3000
# 首次登入會產生一組 Nostr 金鑰對，務必立即備份私鑰
⚠️ 提醒：私鑰只會顯示一次，離開頁面前務必用密碼管理工具妥善保存。團隊導入建議先用測試帳號跑 1-2 週，確認流程順暢後才正式遷移日常溝通。

接入 ACP Agent

# 在 Buzz 設定頁新增 agent provider
buzz agent add claude-code --api-key=YOUR_ANTHROPIC_KEY
buzz agent add codex --api-key=YOUR_OPENAI_KEY

# 在任一頻道啟用該 agent
/agent enable claude-code #dev-team

實戰情境：團隊怎麼用

情境一：Bug 回報直接變 PR

QA 在頻道回報一個 bug，附上重現步驟，直接 @claude-code 請它去看，agent 會自動去讀對應的程式碼、寫修復、開 PR，整個過程開發者不用離開聊天室，審核完直接在 thread 裡按核准合併。

情境二：Code Review 輔助

PR 開出來後，在對應的 review 頻道 @codex 請它先做一輪自動化檢查（風格、明顯 bug、測試覆蓋率），人類 reviewer 只需要專注在架構決策上，省下重複性的檢查時間。

情境三：跨團隊技術文件同步

因為 Buzz 底層走 Nostr，未來如果有多個子公司或外部合作夥伴各自架設 relay，理論上可以做到跨組織的頻道互通，這對外包協作或開源社群維運會是個有意思的應用方向。

常見問題

Buzz 是什麼？跟 Slack 有什麼不同？

Buzz 是 Jack Dorsey 發布的開源協作工具，定位是 Slack + GitHub 的替代方案。最大差異在於底層採用去中心化的 Nostr 協議，沒有單一公司掌控訊息資料，並內建 ACP 支援，可以直接在聊天室裡呼叫 Claude Code、Codex、Goose 等 AI coding agent 工作。

Buzz 支援哪些 AI Agent？

透過 ACP 標準，目前可整合 Anthropic Claude Code、OpenAI Codex CLI、Block 自家的 Goose 等主流 coding agent，未來只要工具支援 ACP 都能接入。

Buzz 免費嗎？可以自架嗎？

Buzz 是開源專案，可以自行部署到自己的伺服器或雲端環境，不需要每月付費給第三方 SaaS，也沒有訊息數或使用者數上限。

團隊要換到 Buzz 需要注意什麼？

因為採用 Nostr 協議，帳號系統跟傳統 Email/密碼登入不同，需要理解公私鑰概念，建議先在小範圍測試環境試跑，並規劃好金鑰備份流程。

總結：值得現在跟進嗎？

Buzz 目前仍是剛發布不久的新專案，生態圈（外掛、第三方整合、社群支援）還在早期階段，不建議完全取代生產環境的核心協作工具。但如果你的團隊已經深度使用 Claude Code 或 Codex，Buzz 提供的原生 ACP 整合是目前市場上少見的體驗，值得先在內部小範圍測試，觀察後續版本迭代速度再決定是否全面導入。
