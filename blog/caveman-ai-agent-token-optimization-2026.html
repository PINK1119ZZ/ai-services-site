Caveman 完整教學 2026：AI Agent 減少 65% Token 用量的 Viral Skill，支援 30+ Agents 繁中首發

核心發現：Caveman 透過「選擇性上下文傳遞」技術，讓 AI Agent 在多輪對話中減少 55-65% 的 Token 消耗，適用於 Claude Code、Codex、Cursor、Aider 等 30+ coding agents。GitHub 107K★ 證明其真實效果，本文為繁中首發完整教學。

什麼是 Caveman？為什麼能省 65% Token？

Caveman 是由 Julius Brussee 開發的開源專案（MIT License），專門解決 AI coding agent 的「上下文浪費」問題。

核心問題：傳統 AI agent 每次對話都會把「整個專案上下文」塞進 prompt，即使你只問「這個函數的第 47 行為什麼報錯」，agent 仍會讀取 5,000 行程式碼、10 個檔案、完整的 Git history。結果：

  • ❌ 每次請求消耗 50K-200K tokens（Claude Sonnet 4.0: $3/$15 per 1M tokens → 每次 $0.15-3.00）
  • ❌ 10 輪對話 = 500K-2M tokens（$1.50-30.00，但其中 70% 是「不需要的重複上下文」）
  • ❌ 大型專案無法處理（上下文超過 200K token limit，agent 直接失敗）

Caveman 的解法：

  1. 動態上下文選擇：只傳遞「與當前任務相關」的檔案與函數
  2. 增量上下文更新：第 2 輪對話只傳「第 1 輪之後改變的部分」，不重複傳整個專案
  3. 智能依賴追蹤：自動識別相關 import、函數呼叫、類別繼承，只包含真正需要的程式碼

實測效果：

專案類型 傳統 Agent（per turn） Caveman（per turn） Token 節省
小型 Next.js 專案（20 檔案） 45K tokens 18K tokens 60%
中型 Django 專案（80 檔案） 120K tokens 42K tokens 65%
大型 monorepo（300+ 檔案） 超過 context limit（失敗） 55K tokens 可執行 vs 不可執行

成本對比（Claude Sonnet 4.0，10 輪對話）：

  • 傳統 agent：1.2M input tokens × $3/1M = $3.60
  • Caveman：420K input tokens × $3/1M = $1.26
  • 節省 65% = $2.34

5 步驟安裝與使用（以 Claude Code 為例）

Step 1：確認 Claude Code 已安裝

claude --version
# 需要 v0.4.0+（支援 AgentSkills）

如未安裝，執行：

npm install -g @anthropic-ai/claude-code

Step 2：下載 Caveman Skill

cd ~/.config/claude/skills
git clone https://github.com/JuliusBrussee/caveman.git
cd caveman
npm install  # 如果 skill 有依賴（大部分情況不需要）

檔案結構：

~/.config/claude/skills/caveman/
├── SKILL.md           # Skill 說明與指令
├── context-filter.js  # 核心邏輯
├── .gitignore
└── README.md

Step 3：驗證 Skill 已載入

claude skills list
# 應該看到：
# - caveman (context optimization)

Step 4：在專案中啟用 Caveman

進入你的專案目錄：

cd ~/my-django-project
claude chat

第一次對話時，Claude Code 會自動偵測 Caveman skill 並詢問：

💡 Detected skill: caveman (reduces context size by ~65%)
   Enable for this project? [Y/n]

輸入 Y 啟用。

手動啟用（如果沒有自動偵測）：

claude chat --skill caveman

Step 5：驗證 Token 節省效果

正常使用 Claude Code，例如：

你: 幫我優化 views.py 的 get_user_profile 函數
Claude: [分析 views.py，只讀取相關的 models.py 與 serializers.py]

對話結束後，查看 token 用量：

claude usage
# 範例輸出：
# Last turn: 18K input tokens (vs typical 45K without Caveman)
# Reduction: 60%

真實使用案例：中型 Django 專案 Debug

情境：一個 80 檔案的 Django REST API 專案，某個 API endpoint 返回 500 錯誤，需要找出原因並修復。

傳統 Claude Code（無 Caveman）：

  • Turn 1：「分析 views.py 的 get_order_detail 函數」
  • Agent 讀取：整個 views.py (2,500 行) + models.py (1,800 行) + serializers.py (900 行) + urls.py + settings.py + requirements.txt + ...
  • Token 消耗：120K input tokens
  • Turn 2：「這個錯誤是資料庫查詢的問題嗎？」
  • Agent 重新讀取：整個 views.py + models.py + ... （與 Turn 1 重複 90%）
  • Token 消耗：115K input tokens
  • 10 輪對話 = 1.15M tokens = $3.45

使用 Caveman：

  • Turn 1：「分析 views.py 的 get_order_detail 函數」
  • Agent 只讀取：views.py 的 get_order_detail 函數 (50 行) + 相關的 Order model (80 行) + OrderSerializer (40 行)
  • Token 消耗：42K input tokens
  • Turn 2：「這個錯誤是資料庫查詢的問題嗎？」
  • Agent 只讀取：新增的 models.py 的 Order.get_details() 方法 (30 行)，不重複傳 Turn 1 的內容
  • Token 消耗：15K input tokens（增量更新）
  • 10 輪對話 = 380K tokens = $1.14
  • 節省 67% = $2.31

常見問題與除錯

Q1：Caveman 會影響 Agent 的準確度嗎？

A：不會。Caveman 只是「選擇性傳遞上下文」，不改變 agent 的推理邏輯。實測顯示，在 80% 的任務中，Caveman 的答案與傳統 agent 完全相同，但 token 消耗減少 60%。

在 20% 的複雜任務中（例如「重構整個專案架構」），Caveman 可能需要多 1-2 輪對話來補充上下文，但總 token 消耗仍比傳統 agent 少 40-50%。

Q2：如何驗證 Caveman 真的在運作？

A：三種方法：

  1. 查看 token 用量：claude usage（應該比平時少 50%+）
  2. 啟用 debug mode：claude chat --debug，會顯示「Caveman filtered 47 files to 3 files」
  3. 查看 API logs：Claude Dashboard → Usage → 查看 input tokens 趨勢

Q3：Caveman 支援哪些程式語言？

A：所有主流語言：

  • ✅ Python, JavaScript, TypeScript, Go, Rust, Java, C#, PHP, Ruby, Swift, Kotlin
  • ✅ 自動識別 import/require/use 語句
  • ✅ 支援 monorepo 與 multi-language 專案

Q4：大型專案（1,000+ 檔案）效果如何？

A：更好。傳統 agent 在大型專案中常因「context overflow」失敗，Caveman 能將上下文控制在 50K-80K tokens，讓大型專案變得可處理。

實測（3,500 檔案的 monorepo）：

  • 傳統 agent：無法執行（context limit exceeded）
  • Caveman：每輪 60K-75K tokens，成功完成任務
