什麼是 Claude Code Auto Mode？

Claude Code Auto Mode 是 Anthropic 在 2026 年 8 月推出的破壞性動作自動審批機制。過去，當 Claude Code 要執行「刪除檔案」、「修改 Git config」、「npm install 第三方套件」等高風險操作時，會跳出確認提示（approval prompt），需要開發者手動按 "Yes" 才繼續。

Auto Mode 的核心改變是：由 AI classifier 自動判斷該動作是否安全，如果信心度超過閾值，就直接執行，不再中斷開發流程。

💡 為什麼要 Auto Mode？
Anthropic 內部研究顯示：人工審查的 false positive rate（誤判安全動作為危險）高達 13.6%，導致開發者頻繁被打斷。而 AI classifier 的 false positive rate 只有 1.2%，同時 false negative rate（漏判危險動作）維持在 0.8% 以下。簡單說：AI 比人更會判斷什麼該攔、什麼該放行。

Auto Mode 如何運作？三層安全機制

很多台灣開發者第一反應是：「AI 自動執行刪除指令？聽起來很危險」。但實際上，Auto Mode 有三層防護：

1. Classifier 預判風險等級

每個 Claude Code 動作在執行前，都會經過破壞性動作 classifier 評分：

  • Low risk（低風險）：讀檔、寫入新檔案、執行測試 → 直接通過，不詢問
  • Medium risk（中風險）：修改現有檔案、安裝 npm 套件 → Auto Mode 開啟時自動通過，關閉時詢問
  • High risk（高風險）：rm -rf、git push --force、修改 .env → 永遠詢問，即使在 Auto Mode 下

⚠️ 重點：Auto Mode 不會自動執行 rm -rf /、DROP DATABASE、git reset --hard HEAD~50 這類明確破壞性指令。這些永遠需要手動確認。

2. Workspace-level Policy Override

如果你是團隊 admin，可以在 workspace settings 設定全域政策：

# .claude/workspace-policy.json
{
  "autoMode": {
    "enabled": false,  // 全團隊強制關閉 Auto Mode
    "allowList": ["npm install", "pytest"],  // 白名單
    "denyList": ["git push", "docker rm"]    // 黑名單
  }
}

3. 仍可手動關閉

即使 8/14 起預設開啟，你隨時可以在 Claude Code 設定關閉：

  1. 打開 Claude Code → Settings → Preferences
  2. 找到 "Auto Mode" 區塊
  3. 取消勾選 "Enable automatic approval for medium-risk actions"

誰應該用 Auto Mode？誰該關掉？

✅ 適合開 Auto Mode 的團隊

  • 快速迭代團隊：startup、prototype 階段，速度優先於絕對安全
  • 中小型專案：資料庫沒有幾 TB、沒有幾千萬用戶，萬一出錯成本可控
  • 已有完整 Git workflow：每個 PR 都走 review + CI，即使 Claude Code 誤判，也會被 PR review 攔下
  • 信任 AI 判斷的開發者：願意給 AI 更多自主權，減少微管理

❌ 應該關掉 Auto Mode 的場景

  • 生產環境直連：如果 Claude Code 有權限直接操作 production database / Kubernetes cluster，請關掉
  • 高度監管行業：金融、醫療、政府專案，需要人工審查每個動作的稽核紀錄
  • 大型 monorepo：幾千個開發者共用一個 repo，一次誤刪影響範圍太大
  • 初次使用 Claude Code：建議先關掉 Auto Mode，熟悉 Claude Code 行為模式後再開啟

如何設定 Auto Mode？完整步驟

方法一：VS Code 插件設定

  1. 確認你的 Claude Code 插件版本 ≥ v2.8.0（2026-08-14 後自動更新）
  2. 打開 VS Code → Extensions → Claude Code → Settings
  3. 找到 "Auto Mode" 區塊：
    • claude.autoMode.enabled → 勾選（預設已開啟）
    • claude.autoMode.riskThreshold → 選擇 "Medium"（預設）或 "Low"（更保守）
  4. 儲存設定，重新載入視窗

方法二：命令列設定（適用 Claude Code CLI）

# 開啟 Auto Mode（Pro/Max/Team 8/14 起預設已開）
claude-code config set autoMode.enabled true

# 設定風險閾值（medium = 平衡，low = 保守）
claude-code config set autoMode.riskThreshold medium

# 查看當前設定
claude-code config get autoMode

方法三：Workspace-level 全域設定（團隊 admin）

在專案根目錄建立 .claude/workspace-policy.json：

{
  "autoMode": {
    "enabled": true,
    "riskThreshold": "medium",
    "allowList": [
      "npm install",
      "pip install",
      "pytest",
      "npm test"
    ],
    "denyList": [
      "git push --force",
      "rm -rf",
      "docker system prune -a"
    ],
    "requireApprovalForPaths": [
      ".env",
      "config/production.yml",
      "terraform/*.tf"
    ]
  }
}
💡 Pro Tip：如果你的團隊有特定高敏感檔案（.env、terraform、Kubernetes manifests），建議用 requireApprovalForPaths 明確列出，這樣 Claude Code 修改這些檔案時永遠會詢問，即使 classifier 判斷為 low risk。

Auto Mode vs 手動審批：實際案例比較

案例一：新增 API endpoint + 測試（中型專案）

任務：寫一個 POST /api/users endpoint，包含 controller + service + 測試。

手動審批模式（Auto Mode OFF）：

  1. Claude Code 建議建立 controllers/user.controller.ts → 你按 "Yes"
  2. 建議安裝 @nestjs/typeorm → 你按 "Yes"
  3. 建議修改 app.module.ts 加入 UserModule → 你按 "Yes"
  4. 建議建立 user.service.spec.ts → 你按 "Yes"
  5. 建議執行 npm test → 你按 "Yes"

總中斷次數：5 次，每次中斷需 3-5 秒切回視窗確認。

Auto Mode（ON）：

  1. Claude Code 建立 controllers/user.controller.ts → 直接執行
  2. 安裝 @nestjs/typeorm → 直接執行
  3. 修改 app.module.ts → 直接執行
  4. 建立測試檔 → 直接執行
  5. 執行測試 → 直接執行

總中斷次數：0 次。你只需在最後 review 一次 diff，確認無誤後 commit。

時間節省：約 2-3 分鐘/任務，一天處理 10 個小任務就省 20-30 分鐘。

案例二：重構 legacy code（大型專案）

任務：把 user.service.ts 裡的 callback hell 改成 async/await。

手動審批（OFF）：Claude Code 每修改一個檔案都詢問 → 你需要一一確認 15 個檔案的改動。

Auto Mode（ON）：Claude Code 一次修改完所有檔案 → 你在最後一起 review git diff。

風險評估：重構屬於 medium risk（修改既有邏輯），但只要有完整測試覆蓋 + PR review，Auto Mode 的效率優勢明顯大於風險。

常見問題 FAQ

Q：Auto Mode 會自動執行 rm -rf / 嗎？

不會。Classifier 會將所有涉及遞迴刪除根目錄、系統目錄的指令標記為 High risk，永遠需要手動確認。即使你手動在 terminal 跑這類指令，Claude Code 也不會參與執行。

Q：如果 classifier 誤判，刪了重要檔案怎麼辦？

三層保護：

  1. Git 保護：所有檔案都在 Git 版本控制下，git checkout -- <file> 就能救回
  2. Undo stack：Claude Code 有內建 undo 功能，按 Cmd+Z 可撤銷上一步動作
  3. Audit log：所有 Auto Mode 執行的動作都會記錄在 .claude/audit.log，可追溯

Q：Free plan 用戶能用 Auto Mode 嗎？

不行。Auto Mode 僅限 Pro / Max / Team 方案（$20-100/月）。Free plan 仍維持手動審批模式。

Q：Cursor / GitHub Copilot 有類似功能嗎？

截至 2026-08-14：

  • Cursor：有類似機制（Cursor Agent Mode），但 classifier 準確率約 82%，略低於 Claude Code 的 89%（詳見 OpenCode vs Cursor vs Claude Code 三大工具比較）
  • GitHub Copilot Agent Mode：8/1 剛推出，目前仍是 beta，預設關閉
  • Windsurf Cascade：沒有 Auto Mode，所有動作都需手動確認（截至 2026-08）

Q：哪些語言/框架支援最好？

Claude Code Auto Mode 對所有語言都支援，但 Node.js / Python / Go 的 classifier 訓練資料最充足，誤判率最低。Rust / Elixir 等小眾語言可能需要更保守的閾值設定。

Q：能看到 classifier 的判斷理由嗎？

可以。開啟 verbose mode：

claude-code config set logging.level debug

之後每個動作執行前，會在 Output 面板顯示：

[Classifier] Action: npm install lodash
Risk level: MEDIUM (confidence: 0.89)
Rationale: Third-party package installation, no file system modification
Decision: AUTO_APPROVE (autoMode=true, threshold=medium)

總結：該開 Auto Mode 嗎？

Auto Mode 是 2026 年 AI-powered development 的必然趨勢。理由很簡單：

  • ✅ 效率提升明顯：PR 量 +25%，中斷次數 -84%
  • ✅ AI 判斷比人準：89% 準確率，false positive 比人工低 10 倍
  • ✅ 安全機制完善：三層防護 + workspace policy + audit log
  • ✅ 隨時可關：不喜歡就關掉，沒有綁定

我們的建議：

  • 如果你是中小型專案 + 有完整 Git workflow → 開 Auto Mode，享受效率紅利
  • 如果你是初次使用 Claude Code → 先關掉，用 1-2 週熟悉行為模式後再開；可以先讀 Claude Code Routines 工作流教學建立基礎認識
  • 如果你是生產環境 / 金融醫療專案 → 關掉，或至少設定嚴格的 denyList + requireApprovalForPaths

最終，Auto Mode 不是「要不要信任 AI」的問題，而是「如何設計安全機制，讓 AI 在可控範圍內發揮最大效率」。2026 年的開發者，需要學會與 AI agent 協作，而不是每一步都微管理。
