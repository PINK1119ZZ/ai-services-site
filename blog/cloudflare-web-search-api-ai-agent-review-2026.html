Cloudflare Web Search API 完整評測 2026：AI Agent 搜尋統一閘道，整合 Ceramic.ai + Exa + Linkup，Cloudflare Birthday Week 正式發布，繁中首發

核心發現：Cloudflare 在 2026 年 10 月 2 日的 Birthday Week 發布 Web Search API，透過既有的 AI Gateway 統一管理三個搜尋 provider（Ceramic.ai、Exa、Linkup）。統一 billing、Zero Data Retention、REST API + Workers binding 多接入方式，讓 AI Agent 獲取即時網路資訊不再需要分別管理多個搜尋 API。HN #3 trending，Product Hunt Oct 5 熱門，繁中零評測，本文首發完整解析與接入教學。

AI Agent 的「猜 URL」問題

如果你有過讓 AI Agent 搜尋網路資訊的經驗，你大概遇過這個問題：Agent 不「搜尋」，它「猜測」。

沒有即時網路存取時，模型只能依賴訓練資料。問它「今天 Hacker News 最熱門的文章是什麼」，它不是去搜尋，而是基於訓練知識編造一個看起來合理的答案。問它「某 GitHub repo 現在有多少 stars」，它給你的可能是 6 個月前的數字。

更糟的情況：Agent 嘗試自行構造 URL 去 curl，然後碰到 429、403、robots.txt 阻擋，整個工作流程崩潰。

解法是把即時搜尋能力直接注入 Agent 的工具集。但這帶來新問題：哪個搜尋 API？用自己的 key 還是代理？怎麼統一 billing？資料隱私怎麼保障？這就是 Cloudflare Web Search API 試圖解決的問題。

Cloudflare Web Search API 是什麼？

簡單說：這是一個透過 Cloudflare AI Gateway 代理多個搜尋 provider 的統一 API 介面。

你不需要分別申請 Ceramic.ai、Exa、Linkup 的帳號和 API key（雖然也可以帶自己的 key）。Cloudflare 把它們整合進 AI Gateway，讓你用同一個 endpoint、同一套 billing 機制、同一個 dashboard 管理所有搜尋請求。

三個搜尋 Provider 的差異

Provider 定位 特點 適合場景
Ceramic.ai AI-native 搜尋 語意理解強，回傳結構化資料 需要深度理解查詢意圖的 Agent
Exa 開發者友好搜尋 精確 URL 搜尋、neural search、HTML 全文回傳 需要完整頁面內容的 research agent
Linkup 企業搜尋 高品質新聞、學術、企業資料覆蓋 需要可靠、最新資訊的業務 agent

這三個 provider 都承諾了兩件事：

  • Zero Data Retention：搜尋請求不被 provider 記錄用於訓練
  • Cloudflare 驗證爬蟲標準：遵守 robots.txt，不爬受保護內容

技術架構：它如何整合進 AI Gateway

理解 Cloudflare Web Search API 的關鍵是先理解 AI Gateway 的角色。

AI Gateway 是 Cloudflare 的 AI 請求代理層，已經整合了 OpenAI、Anthropic、Google、AWS Bedrock 等主要 LLM provider，提供統一的：

  • 請求 logging 與 observability
  • Rate limiting 與 caching
  • Access control
  • Unified billing（用 Cloudflare 點數統一付費）

Web Search API 把「搜尋」視為 AI Gateway 裡的另一種請求類型，和 LLM API 呼叫共存在同一個 gateway 中。這意味著：

  • 搜尋請求會出現在你的 AI Gateway dashboard（和 LLM 呼叫一起）
  • 統一帳單（不再分別管理 LLM 費用 + 搜尋費用）
  • 搜尋可以加入 retry logic、caching、failover 策略

快速上手：三種接入方式

方式一：透過 AI Gateway REST API

curl https://gateway.ai.cloudflare.com/v1/{YOUR_ACCOUNT_ID}/{GATEWAY_ID}/web-search \
  -H "Authorization: Bearer {CF_API_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "exa",
    "query": "Reflection AI Beam 501B open weight model review 2026",
    "limit": 5
  }'

回傳格式為標準化的 JSON，包含 title、url、snippet 三個欄位，不管用哪個 provider 格式都一致。

方式二：Cloudflare Workers binding（最推薦）

// wrangler.toml 配置
[[ai]]
binding = "AI"

// Worker 程式碼（TypeScript）
export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    // 搜尋網路取得最新資訊
    const searchResponse = await env.AI.websearch({
      gatewayId: "default",
      query: "最新 AI 模型 ranking 2026",
      provider: "exa",
      limit: 5,
    });
    const searchResults = await searchResponse.json();

    // 把搜尋結果注入 LLM 呼叫
    const completion = await env.AI.run(
      "@cf/anthropic/claude-opus-4-5",
      {
        messages: [
          {
            role: "user",
            content: `Based on these search results, answer the question:
${JSON.stringify(searchResults)}

Question: 2026 年最強的 open-weight coding model 是哪個？`
          }
        ]
      }
    );

    return Response.json(completion);
  }
};

Workers binding 的優勢是：搜尋和 LLM 呼叫都在同一個 Worker 裡執行，延遲最低，沒有跨服務的網路 round-trip。

方式三：帶自己的 Provider API Key

curl https://gateway.ai.cloudflare.com/v1/{ACCOUNT_ID}/{GATEWAY_ID}/web-search \
  -H "Authorization: Bearer {CF_API_TOKEN}" \
  -H "x-provider-api-key: {YOUR_EXA_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "exa",
    "query": "cloudflare birthday week 2026 announcements",
    "limit": 10
  }'

如果你已有 Exa/Ceramic.ai/Linkup 的帳號，可以帶自己的 key。Cloudflare 不額外收費，只是提供統一的代理和 logging 層。

在 AI Agent 工作流中整合：實際架構示例

場景：自動新聞摘要 Agent

以下是一個在 Cloudflare Workers 上跑的新聞摘要 Agent，每小時抓取最新 AI 新聞並生成繁中摘要：

// 每小時觸發的 Cron Worker
export default {
  async scheduled(event: ScheduledEvent, env: Env, ctx: ExecutionContext) {
    // 1. 搜尋最新 AI 新聞
    const newsSearch = await env.AI.websearch({
      gatewayId: "ai-news-agent",
      query: "artificial intelligence news last 24 hours site:techcrunch.com OR site:theverge.com",
      provider: "ceramic",
      limit: 8,
    });
    const news = await newsSearch.json();

    // 2. 用 LLM 生成繁中摘要
    const summary = await env.AI.run("@cf/google/gemma-4-26b-a4b-it", {
      messages: [{
        role: "user",
        content: `以下是過去 24 小時的 AI 新聞：
${news.results.map(r => `- ${r.title}: ${r.snippet}`).join('\n')}

請用繁體中文寫一份 300 字的重點摘要，條列最重要的 3-5 個發展。`
      }]
    });

    // 3. 儲存到 KV 或發送通知
    await env.NEWS_CACHE.put("latest-summary", summary.response, {
      expirationTtl: 3600
    });
  }
}

費用分析：實際跑起來要多少錢？

Cloudflare Web Search API 在 beta 階段透過 AI Gateway credits 計費，使用提供者的標準定價，Cloudflare 不加價。各 provider 的大概費率（beta 期間可能調整）：

Provider 約略費率 特點
Ceramic.ai ~$0.25 / 1,000 queries AI-native 語意搜尋
Exa ~$1–5 / 1,000 queries（依 plan） 全文內容回傳較貴
Linkup ~$1–3 / 1,000 queries（依 plan） 企業資料品質

對比之下，直接用模型原生搜尋工具（如 Claude 的 web_search）通常在 $10–35 / 1,000 queries 範圍。Ceramic.ai 的 $0.25/1K 讓搜尋成本降低了 40–140 倍。

實際成本估算：

  • 一個每小時跑一次的新聞摘要 Agent：8 次搜尋 × 24 小時 × 30 天 = 5,760 queries/月
  • 用 Ceramic.ai：5,760 × $0.00025 = $1.44/月
  • 一個客服 Agent 每天處理 500 個查詢、每查詢 2 次搜尋：30,000 queries/月
  • 用 Ceramic.ai：30,000 × $0.00025 = $7.50/月

Zero Data Retention 的實際意義

對企業用戶和處理敏感資訊的 Agent 來說，Zero Data Retention 很重要。它意味著：

  • 你的搜尋查詢內容不會被 Ceramic.ai / Exa / Linkup 儲存用於訓練模型
  • 每個請求完成後，provider 不保留任何請求日誌
  • 你的用戶問題、業務查詢不會成為競品的訓練資料

這個承諾是通過 Cloudflare 的合作協議約束的，不只是 provider 單方面的隱私政策聲明。對 GDPR / PDPA 合規需求的企業，這是一個重要的評估點。

Coming Soon：Server Tools 整合

Cloudflare 官方文件提到了「Coming Soon: Server tools」——這意味著 Web Search API 將直接整合進 Claude、GPT 等模型的 function calling / tool use 框架，讓 LLM 可以主動決定「現在要搜尋網路」，而不需要你手動在程式碼裡串接搜尋邏輯。

這個功能完成後，整合方式會更像：

// 未來可能的 Server Tools 整合（預計功能）
const response = await ai.run("@cf/anthropic/claude-opus-4-5", {
  messages: [{role: "user", content: "今天最熱門的 AI 新聞是什麼？"}],
  tools: ["cloudflare:web-search:exa"]  // 模型自主決定何時搜尋
});

目前需要手動先搜尋再注入 context，Server Tools 功能完成後這個過程會更自動化。

適合誰用 Cloudflare Web Search API？

非常適合：

  • 已在使用 Cloudflare Workers / AI Gateway 的開發者
  • 需要即時搜尋功能的 Agent 系統，但不想管多個 API 帳號
  • 有 GDPR/資料隱私合規需求的企業 Agent
  • 需要低成本高頻率搜尋的應用（Ceramic.ai $0.25/1K 很划算）

可能不是最佳選擇：

  • 需要 Google 搜尋結果的場景（目前只有 Ceramic.ai / Exa / Linkup）
  • 非 Cloudflare 基礎設施的純 AWS / GCP 環境（雖然 REST API 可用，但失去 Workers 整合優勢）
  • 需要圖片搜尋或影片搜尋的場景（目前只支援文字搜尋）

Cloudflare Birthday Week 2026 的其他發布

Web Search API 是 Cloudflare Birthday Week 2026（每年 9 月底到 10 月初的年度發布周）的發布之一。同期還有多個 AI 相關功能更新，包括 AI Search 定價模型調整、Workers AI 新模型支援等。

Birthday Week 是 Cloudflare 每年發布最多新功能的時段，通常預告了接下來 12 個月的產品方向。Web Search API 的發布表明 Cloudflare 正在從「CDN + 安全公司」向「AI 基礎設施公司」的方向深度轉型。

總結：接入複雜度低、效益顯著

Cloudflare Web Search API 沒有革命性的技術突破，但它解決了一個真實的整合痛點——在不增加基礎設施複雜度的前提下，給 AI Agent 加上可靠的即時網路搜尋能力。

核心優點：

  • ✅ 統一 billing，不再分別管理多個搜尋 API 帳號
  • ✅ Zero Data Retention，合規更有保障
  • ✅ Ceramic.ai 的 $0.25/1K 定價極具競爭力
  • ✅ Workers binding 讓搜尋和 LLM 在同一個 runtime 執行
  • ✅ Beta 期間可以免費測試基本功能

需要注意：

  • ⚠️ 目前只有三個 provider，無 Google/Bing 搜尋結果
  • ⚠️ Server Tools 整合還在「Coming Soon」
  • ⚠️ Beta 定價可能在 GA 後調整

如果你現在有在 Cloudflare Workers 上跑 AI Agent，這個 API 值得立刻試用（Beta 免費）。如果你在 AWS / GCP 上，評估加入 Cloudflare AI Gateway 作為中間層是否符合你的架構，帶來的好處不只是搜尋，還有整個 LLM 請求的 observability 和 billing 統一。
