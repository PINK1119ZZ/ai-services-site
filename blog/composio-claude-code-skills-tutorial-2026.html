二、Composio 到底解決了什麼問題？

在沒有 Composio 之前，要讓 Claude Code 執行「把 GitHub Issue 自動整理成 Notion 文件」這種任務，你需要：

  1. 為 GitHub 寫 OAuth 2.0 流程（token 申請、刷新、儲存）
  2. 為 Notion 寫另一套 API 整合
  3. 自己管理兩組 API key 和 refresh token
  4. 寫工具函數，讓 Claude 知道「可以呼叫這些工具」
  5. 處理 rate limit、錯誤重試、權限不足等邊緣情況

每一步都是負擔。Composio 把這些全部打包好了。你只需要：

pip install composio-claude
composio login
composio add github
composio add notion

完成。剩下的 OAuth、token 管理、工具描述生成——Composio 全包。

四、5 步驟完成 Claude Code 整合

Step 1

安裝 Composio Python SDK

pip install composio-claude composio-core

需要 Python 3.9+。如果你在使用 Claude Code，通常已有 Python 環境。

Step 2

登入並取得 API Key

composio login

會開啟瀏覽器到 composio.dev 進行 OAuth 登入。完成後 API key 自動寫入 ~/.composio/config.json。

Step 3

加入你需要的整合

# 加入 GitHub
composio add github

# 加入 Slack（需要 Slack workspace 管理員權限）
composio add slack

# 加入 Notion
composio add notion

# 查看已加入的整合
composio integrations

每個 composio add 會引導你完成該服務的 OAuth 授權。token 由 Composio 雲端代為管理，你不需要自己維護。

Step 4

在 Claude Code 中初始化 Composio 工具

import anthropic
from composio_claude import ComposioToolSet, App

client   = anthropic.Anthropic()
toolset  = ComposioToolSet()

# 取得 GitHub 相關的所有工具
tools = toolset.get_tools(apps=[App.GITHUB])

# 也可以混合多個 App
tools = toolset.get_tools(apps=[App.GITHUB, App.SLACK, App.NOTION])
Step 5

讓 Claude 執行跨 SaaS 任務

response = client.messages.create(
    model="claude-sonnet-5-20260701",  # 或任何 Claude 模型
    max_tokens=4096,
    tools=tools,
    messages=[{
        "role": "user",
        "content": (
            "請掃描 composio-dev/composio 這個 repo 的所有 open issues，"
            "把標有 'bug' 標籤的 issues 整理成一份清單，"
            "然後在我的 Notion workspace 新建一個頁面叫做 'Bug Tracker 2026-08-31'，"
            "把清單貼上去。"
        )
    }]
)

# Composio 自動處理工具呼叫循環
result = toolset.handle_tool_calls(client, response, messages=[...])

Claude 會自動決定要呼叫哪些工具、以什麼順序、帶什麼參數。你不需要手動管理工具呼叫循環。

五、掛載 MCP 模式（Claude Code 原生整合）

如果你偏好在 Claude Code 的 .claude/settings.json 中配置 MCP server，Composio 提供了原生 MCP 支援：

# 啟動 Composio MCP server
composio mcp start --apps github,slack,notion --port 8080

然後在 ~/.claude/settings.json 加入：

{
  "mcpServers": {
    "composio": {
      "command": "composio",
      "args": ["mcp", "serve", "--apps", "github,slack,notion"],
      "env": {
        "COMPOSIO_API_KEY": "your_api_key_here"
      }
    }
  }
}

這樣 Claude Code 就可以在對話中直接使用 /tool composio 呼叫任何整合，不需要在程式碼中顯式初始化。對於喜歡 CLI 工作流程的開發者，這是更乾淨的方式。

每當有新 PR 被開啟，自動在 Slack 頻道發一則摘要，包含 PR 標題、作者、變更的檔案清單。

場景二：每日 Issue 報告寄到 Gmail

每天早上 9 點，把昨天新開的所有 GitHub Issues 彙整成報告，寄給 PM 的 Gmail。

tools = toolset.get_tools(apps=[App.GITHUB, App.GMAIL])

prompt = """
找出 my-org/my-repo 過去 24 小時內新開的所有 Issues。
按照 Priority label 排序，生成 HTML 格式報告，
寄送到 pm@company.com，主旨：「Daily Issue Report - {date}」

場景三：把 Notion 需求文件自動轉成 Linear Ticket

PM 在 Notion 寫好需求文件後，讓 Claude + Composio 自動解析並建立對應的 Linear tickets。

tools = toolset.get_tools(apps=[App.NOTION, App.LINEAR])

prompt = """
讀取 Notion 頁面 ID: {page_id} 的內容。
識別所有「功能需求」段落（以 ## 開頭）。
在 Linear 的 Engineering 團隊為每個需求建立一個 ticket，

十、FAQ — 常見問題

Q1：Composio 需要把我的 OAuth token 存在他們的伺服器嗎？
是的，預設情況下 Composio 雲端代為管理 token。這是他們的商業模式——幫你處理 token 刷新和安全儲存。如果你有資安顧慮，可以選擇自託管方案（Open Source 版本，需自行部署）。
Q2：可以同時在多個 Claude 工作階段中使用同一組 Composio 整合嗎？
可以。Composio 的 entity（用戶身份）可以在多個 session 共享，適合多 agent 並行場景。
Q3：Composio 支援 Claude Fable 5 的 1M context 嗎？
支援。Composio 的工具呼叫是標準的 Anthropic API 格式，任何 Claude 模型都可以搭配使用，包括 Fable 5。
Q4：78 個整合夠用嗎？有些工具我用的沒有怎麼辦？
Composio 提供 Custom Tools API，讓你加入任何 REST API 作為自定義工具。定義好 endpoint、參數和描述，Claude 就可以直接呼叫。
Q5：Composio 的免費層有什麼限制？
免費層限制每月 1,000 次工具呼叫，整合數量不受限（所有 78 個都可以用）。對個人專案和測試用途完全足夠。超過後會收到提醒，不會直接中斷服務。
Q6：n8n 用戶有必要換成 Composio 嗎？
不需要「換」，而是看場景。n8n 適合視覺化工作流設計，適合非技術用戶或流程複雜的場景。Composio 適合程式碼優先、需要讓 AI Agent 動態決策工具呼叫順序的場景。兩者可以共存。
