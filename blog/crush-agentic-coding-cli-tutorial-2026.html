一、crush 是什麼？charmbracelet 為何做這個工具

如果你熟悉 Go 生態系，一定聽過 charmbracelet——他們是 bubbletea、lipgloss、glow 等知名終端機 UI 函式庫的作者，在 GitHub 上累積了超過 200,000 顆 star。2025 年底，charmbracelet 推出了 crush：一個為終端機設計、原生支援 agentic coding loop 的 AI CLI 工具。

crush 的誕生背景很清楚：2025-2026 年 AI Coding 工具市場爆炸，但主流選項（Claude Code、GitHub Copilot、Cursor）大多深度綁定 IDE，或需要透過 GUI 操作。charmbracelet 的工程師天生就在終端機生活，他們想要一個「在 tmux 裡跑、不需要滑鼠、能做完整 agentic loop」的工具。crush 就是這個答案。

到 2026 年 8 月底，crush 已累積超過 27,700 顆 GitHub star，在 agentic-ai topic 下排名前五，並受到 HackerNews 社群（367 分，2025 年 7 月）的高度關注。在英文社群有大量討論的情況下，繁中教學至今幾乎是零——這就是本文的切入點。

💡 crush vs Charm：crush 是 charmbracelet 公司的產品，但和他們的 UI 函式庫（bubbletea 等）是不同類別。crush 是一個終端機 AI coding agent，bubbletea 是打造 crush TUI 介面的底層框架。兩者相輔相成。

二、核心功能：Agentic Loop、工具呼叫與多模型支援

crush 的設計哲學可以用三個詞概括：終端機原生、agentic、多模型。以下是每個面向的具體說明：

1. Agentic Loop（自主任務執行）

crush 不只是一個「問問題、看回答」的 chat CLI。它實作了完整的 agentic loop：接收任務 → 規劃步驟 → 呼叫工具（讀/寫檔案、執行指令、搜尋） → 觀察結果 → 重新規劃 → 直到任務完成。這個模式和 Claude Code 的核心架構相同，但 crush 是在終端機環境中以更輕量的方式實現。

典型的 agentic loop 場景：你給 crush 一個 issue 描述，它會自動讀取相關檔案、撰寫修改程式碼、執行測試、根據測試結果修正，最終提交 patch——全部在終端機中完成，不需要切換視窗。

2. 工具呼叫（Tool Use）

crush 內建了一組完整的工具集，讓 AI 模型能真正「動手」：

  • 檔案操作：read_file、write_file、create_file、delete_file、list_dir
  • Shell 執行：run_command（可執行任意 shell 指令，含測試、build、git）
  • 搜尋：search_files（ripgrep 整合）、web_search（可選）
  • Git 整合：git_diff、git_log、git_commit

這些工具讓 crush 能完成真實的開發任務，而不只是生成程式碼片段。

3. 多模型支援

crush 支援透過環境變數切換不同 AI 後端，這是它相較於 Claude Code（鎖定 Anthropic）最靈活的地方：

  • Anthropic：Claude Sonnet 5、Claude Haiku 3.5（預設推薦）
  • OpenAI：GPT-5.4、GPT-5.6 Sol/Terra/Luna
  • Google：Gemini 2.5 Pro、Gemini Flash
  • 本機模型：透過 Ollama 接入 Llama 4.1、Qwen3.8-27B 等
  • OpenRouter：統一 API 閘道，支援 100+ 模型

4. Charmbracelet TUI 美學

這是 crush 與其他 agentic CLI（如 Codex CLI、aider）最大的視覺差距。charmbracelet 用 bubbletea + lipgloss 打造了一個真正好看的終端機介面：彩色語法高亮、進度指示器、可捲動的工具呼叫歷史、清晰的 diff 顯示。在終端機裡工作 8 小時，視覺舒適度不是小事。

三、安裝教學：5 步驟在 macOS / Linux / Windows 跑起來

步驟 1 — 安裝 crush

macOS（推薦用 Homebrew）：

brew install charmbracelet/tap/crush

Linux（直接下載 binary）：

curl -sSL https://github.com/charmbracelet/crush/releases/latest/download/crush_linux_amd64.tar.gz | tar xz
sudo mv crush /usr/local/bin/

Go 用戶（從原始碼編譯）：

go install github.com/charmbracelet/crush@latest

Windows（PowerShell + Scoop）：

scoop bucket add charm https://github.com/charmbracelet/scoop-bucket.git
scoop install crush
步驟 2 — 設定 API 金鑰

在 ~/.bashrc（或 ~/.zshrc）新增你要使用的模型 API key。以 Claude 為例：

export ANTHROPIC_API_KEY="sk-ant-..."
# OpenAI 用戶
export OPENAI_API_KEY="sk-..."
# Google Gemini 用戶
export GOOGLE_API_KEY="AIza..."

設定完成後執行 source ~/.zshrc 讓環境變數生效。

步驟 3 — 初始化設定檔
crush init

這會在 ~/.config/crush/config.yaml 建立設定檔。預設模型為 claude-sonnet-5，可根據需求修改：

# ~/.config/crush/config.yaml
model: claude-sonnet-5        # 預設模型
max_tokens: 8192              # 單次最大回應 token
context_window: 200000        # 上下文視窗（依模型而定）
tool_timeout: 30              # 工具執行超時（秒）
auto_approve_tools: false     # 每次工具呼叫是否需要確認
步驟 4 — 切換到你的專案目錄並啟動
cd ~/my-project
crush

crush 會自動讀取當前目錄的 CRUSH.md（類似 Claude Code 的 CLAUDE.md）作為專案說明。如果沒有，可以先執行 crush init-project 生成一個基本範本。

步驟 5 — 第一個任務：讓 crush 讀懂你的 codebase
# 在 crush TUI 輸入框中輸入：
/summarize
# crush 會自動掃描目錄、讀取關鍵檔案，輸出 codebase 摘要

這一步很重要——讓 crush 建立對你專案的上下文理解，後續任務的準確率會大幅提升。

⚠️ 注意 auto_approve_tools：預設 auto_approve_tools: false，每次工具呼叫（寫檔、執行指令）都需要你按 Y 確認。這是安全設計。在你熟悉 crush 行為之前，建議保持這個設定——別在生產環境設成 true。

五、4 個台灣開發者實戰場景

場景 1：自動化 Code Review

你剛 push 了一個 feature branch，想在發 PR 前先讓 AI 做一輪 review。

cd my-project
crush
# 在 crush 輸入：
請 review 目前 git diff 中的所有修改，重點關注：
1. 潛在的 null pointer / undefined behavior
2. 未處理的錯誤
3. 效能問題（N+1 queries 等）
4. 安全漏洞（SQL injection、XSS）
輸出格式：按嚴重程度排列，每個問題說明位置和修復建議。

crush 會自動執行 git diff、讀取相關檔案，輸出結構化的 review 報告。這個流程用 Claude Haiku 3.5 跑一次約 $0.01-0.05，一個月跑 100 次也不到 $5。

場景 2：從 GitHub Issue 到 Patch

你有一個 bug report，想讓 crush 自動定位問題並提出修復方案：

# 在 crush 中輸入：
Issue #234：使用者在切換語言後，購物車數量顯示不正確。
請：
1. 找出負責語言切換的相關程式碼
2. 找出購物車狀態管理的相關程式碼
3. 找出可能的問題點
4. 提出修復方案並說明原因
5. 如果你有信心，可以直接修改程式碼

crush 的 agentic loop 會自動搜尋相關檔案（ripgrep 整合），讀取程式碼，分析問題，必要時執行測試確認 fix。整個過程你只需要在旁確認每個工具呼叫是否合理。

場景 3：在 VPS 上遠端執行（SSH + tmux）

這是 crush 相較於 IDE-based 工具最大的優勢場景。你在 DigitalOcean 的 VPS 上 SSH 進去：

ssh user@your-vps-ip
# VPS 上已裝好 crush + tmux
tmux new -s coding
cd /var/www/my-app
crush

在本地咖啡廳用 iPhone 的 Termius 都可以繼續讓 crush 在遠端伺服器做 agentic coding，不需要回家開桌機。crush 的純終端機設計讓它在任何 SSH 環境都能完美運作。

場景 4：省錢的模型路由策略

crush 的多模型支援讓你可以根據任務複雜度動態切換模型，大幅降低 API 費用：

# 在 crush config 中設定別名
# ~/.config/crush/config.yaml

profiles:
  cheap:        # 簡單任務用便宜模型
    model: claude-haiku-3-5
    max_tokens: 4096
  standard:     # 一般開發任務
    model: claude-sonnet-5
    max_tokens: 8192
  power:        # 複雜架構設計或大型 refactor
    model: claude-opus-5
    max_tokens: 16384
  free:         # 本機完全免費
    model: ollama/llama-4.1:8b
    max_tokens: 4096
# 切換 profile
crush --profile cheap   # 快速 lint 修復
crush --profile power   # 重大架構重構

七、優缺點總結與適用族群

✅ crush 的優勢

  • 完整 agentic loop，真正能完成複雜任務
  • 支援所有主流 AI 模型，不鎖定單一廠商
  • charmbracelet 品質的 TUI，終端機裡最好看
  • MIT 開源，可以改程式碼加入自己的工具
  • Go 編譯成單一 binary，無依賴地獄
  • SSH + tmux 完美支援，任何裝置可用
  • 本機 Ollama 整合，可以完全離線運作

❌ crush 的不足

  • 社群相對 Claude Code / Cursor 較小
  • 繁中文件和教學資源少（這正是本文存在的原因）
  • 沒有 GUI，習慣滑鼠操作的人需要適應期
  • plugin 生態系尚在發展中
  • CRUSH.md 設定需要自己撰寫，學習曲線稍陡
  • Windows 支援相對 macOS / Linux 較不穩定

crush 最適合誰？

  • 終端機派開發者：你的工作環境是 tmux + neovim / vim，完全不需要 GUI
  • 需要彈性切換模型的開發者：你有多個 API key，想根據任務選最划算的模型
  • VPS / 伺服器端工作者：你需要在遠端伺服器跑 agentic coding，IDE 擴充套件沒辦法用
  • 開源貢獻者：你想要一個真正開源、可以修改的 agentic coding 框架
  • 成本控管嚴格的開發者：你不想花 $20/月固定費，prefer 按用量付費

crush 不適合誰？

  • GUI 習慣者：如果你離不開滑鼠和點擊操作，Cursor 或 IDE 插件更適合
  • 需要大型社群支援的初學者：Claude Code 的中文教學資源目前明顯更多
  • Windows 主力用戶：Windows 上的終端機環境相對複雜，macOS / Linux 體驗更流暢

八、常見問題 FAQ

Q: crush 和 Claude Code 有什麼本質差別？
最大差別是模型綁定。Claude Code 只能用 Anthropic 的模型（Claude Sonnet/Haiku/Opus），而 crush 支援所有主流 AI 廠商的 API，包括 OpenAI、Google Gemini、DeepSeek、以及透過 Ollama 運行的本機模型。如果你有多個 API key 或想靈活切換模型，crush 明顯更有彈性。另外，crush 的 TUI 美學做得比 Claude Code 更精緻。
Q: 安裝 crush 需要什麼前置條件？
基本上只需要一個 AI 模型的 API key（Anthropic / OpenAI / Google 擇一即可）。Go 本身不需要手動安裝，Homebrew / Scoop 安裝會自動處理依賴。如果要用本機模型，需要額外安裝 Ollama。整個安裝流程約 5-10 分鐘。
Q: crush 的 CRUSH.md 和 Claude Code 的 CLAUDE.md 一樣嗎？
概念相同，但格式和讀取機制有細微差異。CRUSH.md 放在專案根目錄，告訴 crush 這個專案的基本資訊、開發規範、常用指令等。crush 在啟動時會自動讀取。一個好的 CRUSH.md 可以明顯提升任務完成率，建議至少包含：技術棧說明、測試執行方式、deploy 指令、程式碼規範。
Q: crush 使用時安全嗎？AI 會不會亂刪我的檔案？
預設設定（auto_approve_tools: false）下，crush 在執行任何工具呼叫（包括寫入/刪除檔案、執行 shell 指令）前都會先顯示將要做的事並等待你按 Y 確認。這個設計讓你完全掌控 AI 的行為。建議在初期使用時保持這個設定，熟悉 crush 的行為模式後再考慮開啟自動批准（僅建議在 CI/CD 環境或有充分備份的情況下）。
Q: crush 支援中文嗎？可以用中文下指令嗎？
完全支援。crush 的 TUI 介面本身是英文，但你可以用中文給指令，AI 模型（Claude / GPT 等）都支援中文輸入輸出。程式碼的繁體中文注解、文件也沒問題。唯一要注意的是，CRUSH.md 建議用英文撰寫，因為 AI 模型對英文上下文的理解通常更精確。
Q: crush 和 OpenCode 哪個比較好用？
兩者都是 Go 語言、多模型支援的 agentic CLI，定位非常相近。主要差異：crush 的 TUI 視覺品質更高（charmbracelet 的本業），OpenCode 在 GitHub stars 上領先更多（172K★ vs 27K★）且社群更大。如果你重視視覺體驗，選 crush；如果你重視社群大小和插件生態，選 OpenCode。兩個都值得試用，安裝各不需要 10 分鐘。
