二、為什麼不繼續用 Mermaid？diagram-design 的差異化優勢

Mermaid.js 是目前 AI agent 最常用的圖表工具，但它有 4 個致命問題：

Mermaid 的 4 大痛點

  1. 語法限制：複雜圖表需要手動調整語法，AI agent 生成的 Mermaid 常常渲染失敗
  2. 樣式貧乏：企業級圖表需要客製化配色、字型、圖例，Mermaid 配置繁瑣
  3. 外部依賴：需要 CDN 或 npm package，離線環境、企業內網難以使用
  4. 圖表類型有限：流程圖/時序圖/甘特圖還行，架構圖/網路拓撲/決策樹支援弱

diagram-design 如何解決？

比較項目 Mermaid.js diagram-design
圖表類型 8 種（流程圖/時序圖/甘特圖等） 44 種（含架構圖/網路拓撲/決策樹）
AI agent 支援 需手動調整語法 原生 prompt → SVG，零調整
外部依賴 需 CDN 或 npm package 自包含 HTML+SVG，零依賴
客製化樣式 需修改 theme 配置 SVG 可直接編輯，CSS 隨意調
企業內網可用 ❌ 需內部架設 CDN ✅ 完全離線可用
授權 MIT MIT

結論：diagram-design 不是取代 Mermaid，而是補上 Mermaid 做不到的 80% 企業級場景。

三、diagram-design 如何運作？技術架構完整解析

3.1 核心設計：Skill-based Architecture

diagram-design 是一組 44 個獨立 skill，每個 skill 對應一種圖表類型。AI agent 收到 prompt 後：

  1. 識別圖表類型：從 prompt 推斷需求（例如「流程圖」「架構圖」「甘特圖」）
  2. 載入對應 skill：選擇 flowchart.skill、architecture.skill 或 gantt.skill
  3. 生成 HTML+SVG：skill 包含完整模板，填入數據後直接輸出
  4. 自包含輸出：HTML 檔案內嵌 SVG，無外部引用，可直接開啟預覽

3.3 為什麼 AI agent 能直接用？Prompt → SVG 的零摩擦設計

傳統圖表工具需要「描述 → 語法 → 渲染」三步驟，AI agent 常在第二步失敗（語法錯誤）。diagram-design 把這三步合併為一步：

// 傳統 Mermaid 流程（AI agent 容易失敗）
User: "畫一個三層架構圖"
AI: "生成 Mermaid 語法"
Render: ❌ 語法錯誤 / 樣式不符 / 需手動調整

// diagram-design 流程（AI agent 零失敗）
User: "畫一個三層架構圖"
AI: 選擇 architecture.skill → 填入數據 → 生成 HTML+SVG
Output: ✅ 完整可用的架構圖，直接開啟 HTML 預覽

為什麼零失敗？

  • 每個 skill 是完整 HTML 模板，AI 只需填入「節點名稱」「連線關係」等結構化數據
  • SVG 樣式預設美觀，企業級配色、陰影、圓角已內建
  • 無需 AI 理解複雜語法（Mermaid/D3.js），只需理解圖表邏輯

七、diagram-design 的 3 個已知限制（與解決方案）

限制 1：複雜互動圖表支援有限

問題：diagram-design 產出靜態 SVG，無法做到 D3.js 等級的互動（hover 顯示詳細資訊、zoom、拖曳）。

解決方案：

  • 輸出 SVG 後，用 D3.js 或 Framer Motion 包一層互動邏輯
  • 用於需求：技術文件、簡報投影、印刷 SOP → 已覆蓋 90% 場景

限制 2：中文字型渲染需額外配置

問題：預設 SVG 用 Arial，中文顯示為「口口口」。

解決方案：

// 在 skill 模板加入中文字型
<style>
  text { font-family: "Microsoft JhengHei", "Noto Sans TC", sans-serif; }
</style>

或產出 SVG 後，用 Figma 匯入 → 替換字型 → 匯出。

限制 3：超大型圖表效能問題

問題：節點數量 > 500 時，SVG 渲染變慢（瀏覽器效能限制）。

解決方案：

  • 拆分大圖為多個小圖（例如微服務架構 → 依服務拆分）
  • 用 Canvas 替代 SVG（diagram-design v3 roadmap）

常見問題

diagram-design 支援哪些 AI coding agent？

支援：Claude Code、Codex、GitHub Copilot、Cursor、Factory Droid、Pi、OpenClaw。只要 agent 支援執行 npm CLI 工具，就能整合 diagram-design。

可以商業使用嗎？

可以。diagram-design 使用 MIT 授權，商業使用、修改、再分發完全自由，無需付費或通知作者。

如何處理中文字型問題？

在 skill 模板 <style> 區塊加入：text { font-family: "Microsoft JhengHei", sans-serif; }。或產出 SVG 後用 Figma 匯入替換字型。

diagram-design 與 Mermaid 可以同時用嗎？

可以。它們不衝突。簡單圖表用 Mermaid（快速語法），複雜架構圖/企業級圖表用 diagram-design（44 種專業圖表 + 零調整）。

離線環境可以用嗎？

可以。diagram-design 產出的 HTML+SVG 是自包含的，無外部 CDN 依賴，完全離線可用，適合企業內網、政府專案。

如何整合進 CI/CD？

在 GitHub Actions / GitLab CI 安裝 diagram-design npm package，執行 claude-code "生成架構圖"，產出檔案 commit 回 repo。詳見本文「企業級最佳實踐」章節。
