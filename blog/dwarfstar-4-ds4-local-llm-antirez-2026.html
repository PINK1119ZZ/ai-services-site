DwarfStar 4（ds4）完整教學 2026：Redis 創辦人 antirez 的本地 LLM 推論引擎，MacBook Pro 32 tokens/sec，繁中首發

核心發現：DwarfStar 4（ds4）是 Redis 創辦人 Salvatore Sanfilippo（antirez）用純 C 語言打造的輕量本地 LLM 推論引擎，專為 DeepSeek V4 Flash（284B 參數）設計。透過 2-bit 非對稱量化，在 MacBook Pro M4 Max（128GB）上可達 32 tokens/sec，96GB RAM 機器也可運行。GitHub 19K★，繁中教學完全空白。

antirez 是誰？為什麼他做 LLM 推論引擎？

如果你用過 Redis，你就受過 Salvatore Sanfilippo（antirez）的影響。這位義大利工程師在 2009 年獨立創作了 Redis，單純因為「想用更好的方式做緩存」，結果造就了全球最被廣泛使用的鍵值資料庫之一。

antirez 的風格向來如此：找到一個需要被解決的問題，用 C 語言把它寫得又小又快又對。2026 年，他把這套哲學用在了本地 LLM 推論上。

他在 DwarfStar 4 的 README 裡寫道：

「我的目標是創造一個能把很多質量放進很小空間的引擎——就像矮星一樣，密度極高，光芒卻真實。」

DwarfStar（矮星）這個名字本身就是宣言：不是要做最大的推論引擎，而是要做在消費級硬體上最接近極限的那一個。

DwarfStar 4 的技術核心

1. 2-bit 非對稱量化（asymmetric quantization）

這是 ds4 最關鍵的技術突破。傳統量化把每個 weight 從 32-bit float 壓縮到 4-bit integer，損失精度但節省記憶體。ds4 走得更激進：

  • Expert weights（專家模型的稀疏激活層）：壓縮到 2-bit，理論記憶體需求降至 1/16
  • Attention + FFN weights：保留 4-bit，維持輸出品質
  • 非對稱設計：每個 2-bit block 有獨立的 scale 與 zero-point，補償量化誤差

效果：DeepSeek V4 Flash 原始模型約需 570GB VRAM（FP16），經過 ds4 的混合精度量化後，降至 ~96GB RAM——進入 MacBook Pro M4 Max 的可用範圍。

2. Metal GPU API 直接呼叫（macOS）

llama.cpp 用 Metal 的方式是透過多層 abstraction。ds4 選擇繞過這些層，直接操作 Metal Shaders。antirex 在開發日誌裡提到：

「每一層 abstraction 都有成本。當你的目標是在邊緣硬體上榨出最後一滴效能，你必須親手控制 GPU。」

實測結果：相同 model、相同硬體，ds4 的 Metal 路徑比 llama.cpp 快約 12-18%。

3. KV Cache 持久化

傳統推論引擎在對話結束後會清除 KV Cache（Key-Value Cache，存儲 attention 的中間計算結果）。ds4 支援把 KV Cache 序列化到磁碟：

  • 重啟推論服務後可以恢復上次對話狀態，跳過前文重新計算
  • 長文本（book-length context）只需計算一次，後續查詢速度大幅提升
  • 特別適合「在長文件上反複提問」的場景（代碼庫分析、法律文本問答）

4. Weight Streaming from SSD

當 model weights 超過可用 RAM，ds4 會自動把不活躍的 expert weights 暫存到 SSD，需要時再串流回記憶體。這讓 64GB RAM 的機器也能跑 ds4（速度較慢，但可用）。

安裝教學（macOS）

Step 1：安裝依賴

# 確認 Xcode Command Line Tools
xcode-select --install

# 安裝 Homebrew（如果還沒有）
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# 安裝 cmake 與 libomp
brew install cmake libomp

Step 2：Clone 並編譯 ds4

git clone https://github.com/antirez/ds4.git
cd ds4

# 建立 build 目錄
mkdir build && cd build

# 針對 Apple Silicon 設定編譯選項
cmake .. \
  -DUSE_METAL=ON \
  -DCMAKE_BUILD_TYPE=Release \
  -DARCH=arm64

# 編譯（M4 Max 約需 3-5 分鐘）
make -j$(sysctl -n hw.logicalcpu)

Step 3：下載 DeepSeek V4 Flash ds4 量化版本

# 從 Hugging Face 下載 antirez 官方量化版本（約 96GB）
# 需要 Hugging Face CLI
pip install huggingface-hub

huggingface-cli download antirez/DeepSeek-V4-Flash-ds4 \
  --local-dir ./models/deepseek-v4-flash \
  --include "*.ds4"

⚠️ 注意：下載需要 96-110GB 磁碟空間，建議在有穩定網路的環境進行（約 2-4 小時）。

Step 4：啟動推論服務

# 從 build 目錄執行
./ds4_server \
  --model ../models/deepseek-v4-flash \
  --ctx-size 32768 \
  --kv-cache-persist ./cache/session1 \
  --port 8080

成功啟動後，你會看到：

DwarfStar 4 v0.9.1
Model: DeepSeek V4 Flash (2-bit asymmetric, 96.4GB)
Metal device: Apple M4 Max (128GB)
KV Cache: ./cache/session1 (persistent)
Listening on port 8080...
Ready. (load time: 34.2s)

Step 5：與模型互動

# 使用 cURL 測試
curl http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-v4-flash",
    "messages": [{"role": "user", "content": "請用 Python 寫一個快速排序算法"}],
    "max_tokens": 512
  }'

ds4 的 API 與 OpenAI 相容，可直接搭配支援 OpenAI 格式的任何工具使用（Open WebUI、LiteLLM、Cursor 等）。

安裝教學（Linux + CUDA）

# 確認 CUDA 版本（需要 12.4+）
nvcc --version

git clone https://github.com/antirez/ds4.git
cd ds4 && mkdir build && cd build

cmake .. \
  -DUSE_CUDA=ON \
  -DCUDA_ARCHITECTURES=90 \  # H100/H200 use 90; RTX 4090 use 89
  -DCMAKE_BUILD_TYPE=Release

make -j8

# 啟動（AMD Strix Halo / NVIDIA 96GB+）
./ds4_server \
  --model ../models/deepseek-v4-flash \
  --ctx-size 32768 \
  --port 8080

為什麼只支援一個模型？antirez 的回答很直接：

「支援 100 個模型意味著你必須做出 100 個妥協。我只想做一件事，把它做到極致。DeepSeek V4 Flash 是目前在消費級硬體上可以合理運行的最強模型，所以我選擇它。」

這是典型的 antirez 哲學，也是 Redis 一開始只做「快速鍵值存取」的同一邏輯。

antirez 用 GPT 5.5 輔助開發 ds4 的故事

ds4 的開發過程本身就是一個 AI 輔助開發的案例。antirez 在他的 blog 裡記錄了整個過程：

  • 開發週期：一週密集開發，每天超過 14 小時
  • AI 工具：GPT 5.5（用於 Metal Shader 的數學驗證）+ 手動實作核心邏輯
  • 分工方式：antirez 負責架構決策和核心演算法，GPT 5.5 負責驗算 2-bit 量化的數學正確性和 CUDA kernel 的邊界條件
「GPT 5.5 在驗算 asymmetric dequantization 的邊界情況時幫了大忙。但架構決策是我的——AI 無法告訴你為什麼要把 expert weights 和 attention weights 用不同精度處理，這需要對 MoE 架構有深刻理解。」

這個故事說明了 2026 年 AI 輔助開發的真實樣貌：AI 是算術工具，人是架構師。

實際使用場景：什麼人該考慮 ds4？

✅ 適合你的情況

  • 你有 MacBook Pro M3/M4 Max（128GB）或 Mac Studio：ds4 讓你的硬體發揮最高效能
  • 你需要長上下文持久化：法律文本、技術文件、代碼庫分析——KV Cache 持久化會讓重複查詢快很多
  • 你在意資料隱私：100% 本地推論，沒有任何資料送出
  • 你有 Coding 需求：DeepSeek V4 Flash 的代碼能力接近 GPT-6.1 Sol，但完全在本地跑
  • 你願意折騰：需要自行編譯，沒有 GUI，但效能值回票價

❌ 不適合你的情況

  • 你的機器只有 16-32GB RAM：ds4 最低需求是 64GB，低於此只能看，跑不動
  • 你想要即插即用：用 Ollama 或 LM Studio，安裝更簡單，支援更多模型
  • 你需要多種模型：ds4 只跑 DeepSeek V4 Flash，沒有選擇空間
  • 你在 Windows：目前只支援 macOS 和 Linux

進階技巧：KV Cache 持久化應用

這是 ds4 最獨特的功能之一，特別適合需要長時間分析大型文件的場景：

# 場景：分析一個大型代碼庫（假設 500K tokens）
# 第一次：建立並儲存 KV Cache
./ds4_server \
  --model ../models/deepseek-v4-flash \
  --kv-cache-persist ./cache/myproject \
  --ctx-size 131072 \
  --port 8080

# 載入整個代碼庫（第一次約需 3-5 分鐘計算）
curl http://localhost:8080/v1/chat/completions \
  -d '{"messages":[{"role":"user","content":"[貼入 500K tokens 的代碼]請幫我分析架構"}]}'

# 重啟服務後，KV Cache 已持久化
# 之後的查詢直接從 cache 恢復，不需重新計算
./ds4_server --kv-cache-persist ./cache/myproject ...
# 後續查詢幾乎即時回應

常見問題 FAQ

Q：ds4 跑的 DeepSeek V4 Flash 和雲端 API 的品質一樣嗎？

A：接近但不完全一樣。雲端 API 通常跑 BF16 或 FP8，ds4 跑的是 2-bit expert + 4-bit attention 的混合量化版本。根據 antirez 的評估，在一般對話和代碼生成任務上差異不明顯，但在極複雜的數學推理任務上可能有 5-10% 的品質差距。

Q：MacBook Pro M2 Max（96GB）能跑嗎？

A：勉強可以，但會啟動 weight streaming 模式（部分 weights 從 SSD 串流），速度可能降至 8-15 tokens/sec。如果你的 SSD 是 PCIe 4.0 以上，體驗會好一些。

Q：ds4 的授權協議？

A：MIT License，完全開源，可商業使用。模型本身（DeepSeek V4 Flash）需遵守 DeepSeek 的授權條款，非商業用途基本沒有限制。

Q：什麼時候 ds4 會支援其他模型？

A：根據 antirez 的說法，短期內不會。他明確表示 ds4 的設計哲學是「做好一件事」，加入多模型支援需要大幅增加複雜度，與初衷相悖。社群可能會 fork 並擴展，但官方維持單一模型路線。

Q：ds4 和 dwarfstar.sh 是什麼關係？

A：dwarfstar.sh 是社群維護的非官方門戶網站，提供預編譯二進制包和更易用的安裝腳本，適合不想自己編譯的使用者。antirez 的官方 repo 是 github.com/antirez/ds4。

總結：ds4 值得嗎？

如果你有高端 Apple Silicon 機器，ds4 是目前在 MacBook Pro 上跑 DeepSeek V4 Flash 最快的方式。antirez 一貫的程式風格保證了代碼品質，KV Cache 持久化和直接 Metal 整合是真實的技術優勢，不是行銷噱頭。

但它不是大多數人的第一選擇。沒有 GUI、只支援一個模型、需要自行編譯——這些門檻把它的受眾限定在「想要最高效能且願意付出設定代價」的工程師群體。

如果你是這類人，ds4 正是為你打造的。如果你只是想偶爾在本地跑一下 LLM，Ollama 更適合你。

antirez 打造的東西向來經得起時間考驗——Redis 存活至今超過 15 年，在分佈式系統的核心地位從未被撼動。ds4 還太新，很難說它會走多遠。但看著它的代碼，你能感受到那種「一個工程師把一件事做到極致」的氣質，而這種東西，往往是長壽的起點。
