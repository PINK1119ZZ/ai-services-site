GPT-6.1 Sol Cached Input 完全攻略：如何省 95% 成本

GPT-6.1 Sol 最殺手級功能：cached input $0.10/M tokens（比標準 $2/M 省 95%、比 GPT-6 Sol cache $0.20/M 省 50%）。正確使用 cache 可讓長期部署成本暴降。

Cached Input 運作原理

  1. 首次請求：標記可 cache 的 messages（如 system prompt、codebase context），OpenAI 儲存 cache key。
  2. 後續請求：若 cache key 命中（5-10 分鐘內），該部分 input 僅計費 $0.10/M（省 95%）。
  3. Cache 失效：超過 5-10 分鐘或 cache key 變更，需重新建立 cache（恢復標準計費）。

最佳實踐：台灣開發者如何用好 Cache

  • Coding Assistant：每日開工時首次傳送完整 codebase context（首次 $2/M），後續 29 次修改僅需 $0.10/M → 每月省 80%+。
  • RAG with Fixed Knowledge Base：固定文件庫（如公司內部文件）標記為 cacheable，每次 query 僅計費新問題部分。
  • Multi-turn Agent：system prompt + 前 N 輪對話標記 cacheable，新對話延續舊 context 時成本暴降。

Cache 使用範例（Python）

from openai import OpenAI

client = OpenAI()

response = client.chat.completions.create(
    model="gpt-6.1-sol",
    messages=[
        {
            "role": "system",
            "content": "你是專業的 Python coding assistant...",
            "cache_control": {"type": "ephemeral"}  # 標記為可 cache
        },
        {
            "role": "user",
            "content": "請幫我 review 這段程式碼..."
        }
    ]
)

關鍵提醒：cache 有效期 5-10 分鐘，若間隔超過 10 分鐘需重新建立。建議在「連續工作時段」內密集使用 GPT-6.1 Sol，最大化 cache hit rate。
