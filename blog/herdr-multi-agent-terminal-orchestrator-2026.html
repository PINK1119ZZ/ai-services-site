Herdr 完整教學 2026：讓多個 Claude Code 和 Codex 同時工作的 Agent-Native Terminal 管理器，35K★ Rust Apache-2.0，繁中首發

核心功能：Herdr 是一個 Rust 寫的 agent-native terminal multiplexer。它不是一個終端機模擬器，而是一個跑在背景的 server，讓你的多個 AI coding agent（Claude Code、Codex、OpenClaw 等）在不同 pane 裡同時工作，並且自動追蹤每個 agent 是「working / blocked / idle / done」狀態。Apache-2.0 授權，YC F26 batch，35K+ GitHub stars，Warp 官方推薦為「multi-agent 的唯一必裝工具」。

為什麼你需要 Herdr？一個真實場景

想像一下你在做一個全端重構：

  • Claude Code 正在 src/ 目錄裡跑測試，需要 20 分鐘
  • 另一個 Claude Code 正在 docs/ 目錄裡更新文件
  • Codex 正在 infra/ 目錄裡修 Terraform 配置

如果你用傳統的 tmux，你有三個 pane，但你沒辦法知道哪個跑完了，哪個卡住在等你輸入，哪個還在忙。你需要輪流查看每個 pane——這就是所謂的「agent 管理負擔」。

Herdr 解決的正是這個問題。

Warp 的工程師在他們 2026 年的「Best Terminal for AI Coding Agents」評測中說得很直接：

「使用任何終端機模擬器加上 Herdr。你得到持久性、以及一個 sidebar 標記每個 agent 是 working、blocked 或 done 的狀態，還有一個 socket API 讓 agent 可以呼叫來 spawn siblings 並互相等待。」

Herdr 是什麼？技術架構解析

核心定位：不是終端機，是 Agent Runtime

這是理解 Herdr 最重要的一點：Herdr 不是一個終端機模擬器（不像 iTerm2、Ghostty、WezTerm）。它是一個在背景持續運行的 server，你在自己最喜歡的終端機模擬器裡連接它。

這個架構的優勢：

  • 關掉終端機不會停止 agent：因為 Herdr server 在背景持續跑，agent 工作繼續進行
  • 重開機後恢復：Herdr 會把 layout 和 session 狀態存到磁碟，重啟後自動恢復
  • 跨裝置存取：透過 collie（社群 PWA）或 herdrm（macOS native app），可以從手機或另一台電腦查看 agent 狀態

Agent 狀態偵測的技術原理

Herdr 用什麼方式判斷一個 agent 的狀態？根據其 README 和 Developer's Digest 的深度分析：

  • Working：Pane 有 CPU 活動，且輸出在更新
  • Blocked：Agent 輸出了等待使用者輸入的提示，但超過設定的 timeout 沒有繼續（例如 Claude Code 的「Do you want to proceed? [y/n]」）
  • Idle：No CPU activity，prompt 在等輸入，但不是 blocked 狀態（通常是 agent 完成了一個任務，在等下一個指令）
  • Done：Agent 主動發出完成訊號（透過 socket API），或 process 正常結束

這個狀態機設計讓你一眼就能看到：「哪個 agent 正在忙、哪個在等我、哪個已經完成了」——不需要輪流查看每個 pane。

快速安裝教學

安裝 Herdr binary

# macOS（Homebrew）
brew install herdrdev/tap/herdr

# Linux（curl 安裝）
curl -fsSL https://herdr.dev/install.sh | sh

# 從 source 建置（需要 Rust toolchain）
git clone https://github.com/herdrdev/herdr
cd herdr
cargo build --release
# Binary 在 target/release/herdr

# 確認安裝
herdr --version
# herdr v0.9.1

啟動 Herdr Server

# 啟動背景 server
herdr-server start

# 確認 server 狀態
herdr-server status
# connected · 0 workspaces · 0 agents · nobody attached

# 設定開機自動啟動（macOS）
herdr-server install-autostart

# 設定開機自動啟動（Linux systemd）
herdr-server install-systemd

建立第一個 Multi-Agent Workspace

# 連接到 Herdr server（在你的終端機模擬器中）
herdr attach

# 建立一個新的 workspace
herdr workspace new my-project

# 在 workspace 中開啟第一個 agent pane
herdr pane new --name "backend-refactor" --cwd ~/projects/backend

# 在同一個 workspace 開啟第二個 agent pane
herdr pane new --name "tests" --cwd ~/projects/backend

# 開啟第三個 pane
herdr pane new --name "docs" --cwd ~/projects/docs

啟動 AI Coding Agents

# 在 backend-refactor pane 中啟動 Claude Code
herdr exec backend-refactor "claude --dangerously-skip-permissions '重構 auth 模組，保持向後相容'"

# 在 tests pane 中啟動另一個 Claude Code
herdr exec tests "claude '為 auth 模組寫完整單元測試'"

# 在 docs pane 中啟動 Codex
herdr exec docs "codex '更新 auth 模組的 API 文件'"

# 查看所有 agent 狀態
herdr status
# my-project
#   backend-refactor  [working]   claude · 00:04:23
#   tests             [idle]      claude · waiting for input
#   docs              [working]   codex  · 00:02:11

Socket API：讓 Agent 互相協調

Herdr 最進階的功能是 Socket API——讓 agent 可以透過程式方式與 Herdr server 溝通，實現 agent 之間的協調。

實用案例：Agent A 完成後自動觸發 Agent B

#!/bin/bash
# agent-orchestrator.sh
# 讓第一個 agent 完成後自動通知 Herdr，觸發下一個任務

# Claude Code 完成重構後，透過 socket 通知 Herdr
claude --dangerously-skip-permissions '重構 auth 模組' && \
  herdr signal done backend-refactor && \
  herdr exec tests "claude '現在執行所有測試'"
// 在 Node.js agent script 中使用 Herdr Socket API
const net = require('net');

function notifyHerdr(pane, status) {
  const socket = net.connect('/tmp/herdr.sock', () => {
    socket.write(JSON.stringify({
      action: 'signal',
      pane: pane,
      status: status  // 'working' | 'blocked' | 'idle' | 'done'
    }));
    socket.end();
  });
}

// 任務完成後通知 Herdr
async function runTask() {
  notifyHerdr('my-pane', 'working');
  // ... 執行任務 ...
  notifyHerdr('my-pane', 'done');
}

Agent Spawn：讓 Agent 自動產生子 Agent

// Claude Code 可以透過 Herdr API spawn 新的 agent 處理子任務
const spawnSubAgent = (task, cwd) => {
  exec(`herdr pane new --name "${task}" --cwd "${cwd}"`, (err) => {
    if (!err) {
      exec(`herdr exec "${task}" "claude '${task}'"`)
    }
  });
};

// 例如：發現需要同時更新 5 個微服務時
const services = ['auth', 'user', 'payment', 'notification', 'analytics'];
services.forEach(svc => {
  spawnSubAgent(`update-${svc}`, `~/services/${svc}`);
});

與 OpenClaw 整合：AutoDev AI 的實際工作流

我們在 AutoDev AI 的日常開發中，把 Herdr 和 OpenClaw 結合起來使用。以下是我們的配置：

# ~/.herdr/config.toml
[server]
socket = "/tmp/herdr.sock"
log_level = "info"
persist_on_exit = true

[defaults]
shell = "/bin/bash"
working_state_timeout = 300   # 5 分鐘沒有輸出就標記為 idle
blocked_detection = true      # 自動偵測等待使用者輸入

[workspaces.autodev]
description = "AutoDev AI 日常開發"
panes = [
  { name = "openclaw-agent", cwd = "~/ai-services-site" },
  { name = "seo-writer", cwd = "~/ai-services-site" },
  { name = "builder", cwd = "~/ai-services-site" },
]
# 啟動 AutoDev AI workspace
herdr workspace attach autodev

# 查看 agent 狀態（帶 CPU 和記憶體資訊）
herdr status --verbose

#   openclaw-agent  [working]   CPU: 45%  MEM: 1.2GB  00:12:34

常見問題與解答

Q：Herdr 和 tmux 有什麼根本差異？

tmux 把每個 pane 視為一個匿名的 terminal 進程，完全不知道裡面跑的是什麼。Herdr 知道每個 pane 裡跑的是 AI coding agent，並且主動監控其狀態。這是「Generic multiplexer」和「Agent-native multiplexer」的根本差異。

Q：Herdr 需要什麼系統需求？

Herdr 是一個單一 Rust binary，沒有 runtime 依賴。支援 macOS（Intel & Apple Silicon）、Linux（x86_64 & ARM64）。Windows 支援仍在開發中（可透過 WSL2 使用）。最低需求：1 CPU core，256MB RAM。

Q：Herdr 的 Apache-2.0 授權意味著什麼？

Apache-2.0 是非常寬鬆的開源授權。你可以：免費商業使用、修改、再分發，只需要保留原始 copyright 聲明和 Apache-2.0 授權文件。不需要開放你的修改版本的源碼（不是 copyleft）。

Q：Herdr 有收集任何遙測資料嗎？

根據官方 README：「no telemetry」。Herdr server 完全在本地或你的 VPS 上運行，不向任何外部 endpoint 傳送資料。

Q：agent 在 Herdr 裡跑「blocked」狀態是什麼情況？

Blocked 代表 Herdr 偵測到 agent 在等待使用者輸入（例如 Claude Code 問「Do you want to run this bash command?」），但超過了你設定的 blocked_detection_timeout（預設 30 秒）沒有繼續。這時 sidebar 會標紅，提醒你去處理。

適合 Herdr 的開發場景

✅ 最適合

  • 大型重構：同時在多個模組/服務並行工作，追蹤每個任務的進度
  • 遠端開發：在 VPS 上跑 agent，本地透過 herdrm 或 SSH 監控
  • 長時間任務：不擔心關閉終端機會中斷 agent，安心離開去做其他事
  • Pipeline 自動化：用 Socket API 讓 agent 之間自動協調，實現零介入的多步驟工作流
  • 隱私敏感環境：本地 Apache-2.0 工具，無遙測，適合企業內部使用

❌ 不太適合

  • 單一 agent 快速任務：如果你只是跑一個 Claude Code 做一個小修改，tmux 或直接開 terminal 就夠了
  • 需要 cloud-hosted agent 的場景：如果你想把 agent workload 卸載到雲端（而非自己 VPS），Warp Factory 可能更適合
  • Windows 原生使用者：目前只能透過 WSL2 使用，體驗不如原生 Linux/macOS
