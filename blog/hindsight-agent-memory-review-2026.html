AI Agent 為什麼需要「記憶」？

大多數人對 AI Agent 的第一個挫折都是：它記不住你告訴過它的事。

告訴 Claude Code 你偏好用 TypeScript strict mode，下次 session 又要重說。跑了一週的 LangGraph 自動化流程，遇到錯誤卻不記得上次是怎麼修的。CrewAI 的 Agent 跑完一個研究任務，下個任務繼續從零開始。

這不是模型能力的問題。GPT-6.1 Sol、Claude Opus 4、Gemini 4 Argon 都已經很強了。問題在於：context window 是揮發性的。每次新的 session，記憶清零。

這就是 Hindsight 要解決的核心問題。

Hindsight 是什麼？

Hindsight 是由 Vectorize.io 開發並開源的 AI Agent 記憶管理系統。它的定位非常清楚：讓你的 Agent 在不同 session、不同任務之間保留結構化的長期記憶，而不只是依賴 context window 裡的短期記憶。

GitHub 上 vectorize-io/hindsight 目前有 27,000+ stars，在 2026 年 9 月曾連續多天排在 GitHub Trending #1-2，顯示開發者社群對這個問題的迫切需求。

Hindsight 的核心概念

Hindsight 把 Agent 記憶分成三個層次：

  • Episodic Memory（情節記憶）：具體事件的記錄。例如「2026-10-01，用戶要求優化 API response time，採用了 Redis caching 方案」。
  • Semantic Memory（語義記憶）：從情節中提煉出的通用知識。例如「這個用戶偏好 TypeScript，不喜歡 any 類型」。
  • Working Memory（工作記憶）：當前 session 的即時上下文，自動注入到每次呼叫的 prompt 中。

這三層記憶的組合，讓 Agent 能夠做到：

  • 記住跨 session 的用戶偏好
  • 學習並沿用過去有效的問題解法
  • 在長期運行的自動化流程中積累領域知識

LongMemEval Benchmark：為什麼 91.4% 很重要？

衡量 Agent 記憶系統的難點在於：你怎麼量化「它記得多好」？

LongMemEval 是目前學術界認可度最高的 Agent 長期記憶 benchmark，設計了需要跨越數百次對話才能回答的問題。例如：

「你在 3 個月前向我推薦過一個 Python 套件來處理 PDF。那個套件叫什麼？」

要回答這個問題，系統必須：
1. 從數百個 session 紀錄中精準定位相關記憶
2. 理解問題的語意並正確關聯
3. 以自然語言組織回答

LongMemEval 的滿分是 100%，多數現有方法落在 50-70% 區間。Hindsight 拿到 91.4%，是目前所有公開方案中的最高分（SOTA）。

相比之下：

Hindsight 的技術架構

記憶提取引擎（Memory Extraction Engine）

Hindsight 的核心競爭力是它的記憶提取算法。傳統 RAG 方案的問題是：把所有對話 chunk 丟進向量資料庫，查詢時靠語意相似度拉出相關片段。這在短期記憶下表現不錯，但在長期（數百次對話）場景下，相關的記憶片段可能在語意上距離較遠。

Hindsight 改用 三階段記憶處理流程：

  1. Event Detection：即時偵測對話中值得記憶的事件（用戶偏好、決策、錯誤修正等）
  2. Memory Consolidation：定期把情節記憶壓縮成語義記憶，去除冗餘，保留精華
  3. Contextual Retrieval：查詢時結合語意搜尋 + 時序關聯 + 重要性加權，提升精準率

支援框架

Hindsight 提供官方 SDK，支援：

  • Claude Code（MCP server 方式整合）
  • LangGraph（node 插入方式）
  • CrewAI（memory provider 替換）
  • OpenAI Agents SDK
  • LlamaIndex
  • 純 Python SDK（任何框架通用）

安裝教學：Docker One-liner 自架

Hindsight 最快的啟動方式是官方 Docker Compose。以下是在有 Docker 的機器（本機或 VPS）上跑起來的完整步驟。

需求

  • Docker 24.0+（本機或 VPS）
  • 至少 2 GB RAM
  • PostgreSQL（Hindsight 自帶 compose 會一起啟動）

步驟一：Clone 並啟動

git clone https://github.com/vectorize-io/hindsight.git
cd hindsight
docker compose up -d

Compose 會自動啟動：

  • hindsight-server（記憶管理 API，port 8080）
  • postgres（記憶儲存後端）
  • pgvector（語意搜尋向量擴充）

步驟二：取得 API Key

# 等容器啟動後（約 20-30 秒）
curl http://localhost:8080/api/v1/keys \
  -X POST \
  -H "Content-Type: application/json" \
  -d '{"name": "my-agent"}'

# 回傳：{"key": "hs_live_xxxxxxxxxxxx"}

步驟三：安裝 Python SDK

pip install hindsight-sdk

步驟四：整合進你的 Agent

以 Python SDK 為例（通用，不依賴框架）：

from hindsight import HindsightClient

hs = HindsightClient(
    api_key="hs_live_xxxxxxxxxxxx",
    base_url="http://localhost:8080"
)

# 每次對話結束後儲存記憶
hs.remember(
    agent_id="my-assistant",
    user_id="user-123",
    messages=[
        {"role": "user", "content": "我偏好用 TypeScript strict mode"},
        {"role": "assistant", "content": "好的，我記住了。之後的程式碼會用 TypeScript strict mode。"}
    ]
)

# 下次對話開始前，取回相關記憶
memories = hs.recall(
    agent_id="my-assistant",
    user_id="user-123",
    query="TypeScript 偏好設定"
)
print(memories.context)  # 注入到你的 system prompt

整合 Claude Code（MCP Server 方式）

如果你使用 Claude Code，Hindsight 提供 MCP Server 整合，可以讓 Claude Code 直接讀寫記憶，不需要自己管理 API 呼叫。

在 Claude Code 設定 MCP

# ~/.config/claude/mcp.json
{
  "servers": {
    "hindsight": {
      "command": "npx",
      "args": ["-y", "@vectorize-io/hindsight-mcp"],
      "env": {
        "HINDSIGHT_API_KEY": "hs_live_xxxxxxxxxxxx",
        "HINDSIGHT_BASE_URL": "http://localhost:8080"
      }
    }
  }
}

設定完成後，Claude Code 每次 session 結束時會自動把重要決策、偏好和錯誤修正記入 Hindsight。下次啟動時，它會從 Hindsight 拉取相關記憶並注入 working context。

實際效果：你告訴 Claude Code 「這個 repo 用 pnpm，不用 npm」，下週打開新 session 它還記得。

整合 LangGraph

在 LangGraph workflow 中，Hindsight 作為一個 memory node 插入：

from langgraph.graph import StateGraph
from hindsight.integrations.langgraph import HindsightMemoryNode

# 建立記憶節點
memory_node = HindsightMemoryNode(
    client=hs,
    agent_id="my-langgraph-agent"
)

builder = StateGraph(AgentState)
builder.add_node("recall_memory", memory_node.recall)
builder.add_node("agent", my_agent_node)
builder.add_node("save_memory", memory_node.save)

# recall → agent → save 的流程
builder.add_edge("recall_memory", "agent")
builder.add_edge("agent", "save_memory")

Hindsight Cloud：零 Ops 付費版

如果你不想管 Docker、不想維護 PostgreSQL，Vectorize.io 提供 Hindsight Cloud，這是一個 fully managed 的 Hindsight 服務。

Hindsight Cloud 的特點

  • Usage-based 計費：按實際記憶操作量收費，不需要預購固定方案
  • 全球多區域：自動就近路由，低延遲
  • 自動備份：記憶資料不會因為機器故障而流失
  • API 完全相容：把 base_url 換成 https://api.hindsight.cloud，程式碼無需其他修改
  • Dashboard：可視化查看 Agent 記憶內容、搜尋歷史記憶

自架 vs Cloud 比較

比較項目 自架（Docker） Hindsight Cloud
費用 VPS 費用（$6-24/月） Usage-based（按需付費）
設定難度 需要 Docker 基礎知識 申請 API Key 即可
資料掌控 完整自主 第三方代管
適合場景 企業內網、資料敏感 快速啟動、個人/小團隊
維護負擔 需自行更新、備份 零 Ops

對於想快速驗證效果的開發者，建議先用 Hindsight Cloud。如果記憶資料需要 on-premise 部署（金融、醫療、企業敏感資料），則自架。

Hindsight 適合哪些場景？

1. Claude Code 長期開發助手

這是 Hindsight 最直接的個人開發者場景。如果你每天用 Claude Code 工作，它記得：

  • 你的 repo 慣用哪些套件和風格
  • 上次遇到哪個 bug 以及怎麼解的
  • 你說過不喜歡哪些架構決策

2. 客服 AI Agent

客服 Agent 透過 Hindsight 記住每個用戶的歷史問題、偏好設定和已解決的問題，不需要每次重新建立上下文。相比起「每次 session 都 full context 注入」，Hindsight 的結構化記憶讓相關性更精準，也節省大量 token 費用。

3. 研究自動化 Agent

運行週期較長的研究 Agent（例如每週爬取競品資訊）可以透過 Hindsight 累積知識庫：「這個競品上次的定價是 X，現在變成 Y」——不需要每次重跑所有歷史資料。

4. CrewAI 多 Agent 共享記憶

在 CrewAI 多 Agent 協作場景中，Hindsight 可以作為共享記憶後端，讓不同 Agent（Research Agent / Writer Agent / QA Agent）存取同一份記憶庫，避免各 Agent 各自為政。

Hindsight vs Mem0：主要差異

Mem0（mem0.ai）是目前 Hindsight 最直接的競品，也有不少台灣開發者在用。主要差異：

比較項目 Hindsight Mem0
LongMemEval 91.4% SOTA 68.9%
開源授權 MIT（完全自由使用） Apache 2.0
Claude Code 整合 官方 MCP Server 自行實作
記憶架構 3 層（Episodic / Semantic / Working） 扁平向量儲存
自架難度 Docker Compose（簡單） 需自行設定後端
GitHub Stars 27K★ ~22K★

如果你在乎 benchmark 分數和 Claude Code 官方整合，Hindsight 是目前更好的選擇。Mem0 的優點是生態較成熟，有更多第三方教學和案例。

Hindsight 的限制與注意事項

  • 記憶提取延遲：Hindsight 的 Contextual Retrieval 比簡單 RAG 慢（約 200-500ms 額外延遲），在高頻場景需要考量
  • Storage 成長：長期運行的 Agent 記憶庫會持續增長，需要定期做 memory consolidation（Hindsight 有自動排程，但需要開啟）
  • 多用戶隔離：預設是用 user_id 隔離，確保不同用戶記憶不會混入，但多租戶部署需要額外設定
  • Cloud 定價未公開：Hindsight Cloud 的 usage-based 定價目前需要透過 Vectorize.io 官網申請，尚無公開費率表

總結：要用 Hindsight 嗎？

如果你符合以下任一條件，Hindsight 值得立即試用：

  • ✅ 每天用 Claude Code 開發，希望它記住你的偏好
  • ✅ 在跑 LangGraph / CrewAI Agent，需要跨 session 保留狀態
  • ✅ 在建構面向用戶的 AI 助手，需要個性化記憶
  • ✅ 對「記憶」這件事有嚴格的準確率要求

如果你只是在跑一次性的 AI 任務，或者 context window 已經夠用，不需要特別加記憶系統。

Hindsight 的 MIT 授權和 Docker one-liner 安裝意味著試用成本趨近於零。先跑起來，接入你最常用的一個 Agent，感受一下差距，再決定是否深度整合。
