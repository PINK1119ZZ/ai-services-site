Progressive Disclosure：為什麼能節省 63% Token？

傳統 AI skills 的問題：大部分 AI agent 框架（包括 Addy Osmani 的 agent-skills）會在每次對話開始時，把所有 skills 的完整內容一次性注入 context window。這導致：

  • Token 浪費：你可能只需要「重構程式碼」skill，但 AI 卻要讀完「寫測試」、「API 文檔」、「架構設計」等 20+ 個 skills
  • 速度變慢：更多 token = 更長的處理時間
  • 費用增加：Claude API 按 token 計費，浪費的 token 會累積成龐大費用

Matt Pocock Skills 的解決方案：Progressive Disclosure

Progressive disclosure（漸進式揭露）是一種 UX 設計原則，Matt Pocock 將它引入 AI skills：

  1. 第一層：摘要目錄 — AI 只看到每個 skill 的簡短描述（20-50 字）
  2. 第二層：按需載入 — AI 判斷需要哪個 skill，再用 /codebase-design、/domain-modeling 等指令載入完整內容
  3. 第三層：深度細節 — 如果需要更多細節，可以再載入特定章節（例如 /codebase-design#folder-structure）

實測效果：Matt Pocock 團隊測試發現，使用 progressive disclosure 後，平均每次對話的 context token 從 15,000 tokens 降到 5,500 tokens，節省 63%。

Matt Pocock Skills v1.0 完整安裝教學

支援平台

Matt Pocock Skills 支援所有主流 AI coding assistant：

  • Claude Code（Desktop + Terminal）
  • Cursor（透過 .cursorrules）
  • Windsurf（透過 .windsurfrules）
  • GitHub Copilot
  • Zed Editor
  • 任何支援 MCP（Model Context Protocol）的工具

方法 1：快速安裝（推薦，5 分鐘）

# 1. Clone 專案
git clone https://github.com/mattpocock/skills.git
cd skills

# 2. 複製到你的專案
cp -r .skills /path/to/your/project/

# 3. （Cursor 用戶）建立 .cursorrules
cp .cursorrules /path/to/your/project/

# 4. （Windsurf 用戶）建立 .windsurfrules  
cp .windsurfrules /path/to/your/project/

# 5. （Claude Code 用戶）加入 claude_desktop_config.json
# 參考下方設定

方法 2：全域安裝（適合多專案）

# 1. Clone 到家目錄
cd ~
git clone https://github.com/mattpocock/skills.git

# 2. 建立全域 symlink
ln -s ~/skills/.skills ~/.skills

# 3. 在每個專案根目錄建立 symlink
cd /path/to/your/project
ln -s ~/.skills .skills

Claude Code Desktop 設定

編輯 ~/Library/Application Support/Claude/claude_desktop_config.json（macOS）或 %APPDATA%\Claude\claude_desktop_config.json（Windows）：

{
  "mcpServers": {
    "skills": {
      "command": "node",
      "args": [
        "/path/to/skills/mcp-server.js"
      ]
    }
  }
}

v1.0 新增的核心 Skills

1. /codebase-design — 專案架構設計

這是 v1.0 的重量級新增！專門教 AI 如何組織大型專案的資料夾結構、模組分層、依賴管理。

適用場景：

  • 開始新專案，不確定資料夾怎麼分
  • 重構老專案，想改善結構
  • 多人協作，需要統一規範

使用範例：

我要建立一個 Next.js 14 電商專案，包含：
- 商品列表 + 購物車
- 會員系統（註冊/登入）
- 金流串接（綠界）
- 後台管理

請用 /codebase-design 建議最佳資料夾結構。

2. /domain-modeling — 領域模型設計

v1.0 另一大亮點。幫助 AI 理解你的業務邏輯，設計出語意清晰、可擴展的資料模型。

為什麼重要：大部分 AI 在設計資料模型時容易過度工程化（over-engineering）或過度簡化。/domain-modeling 內建了 DDD（Domain-Driven Design）原則，讓 AI 依照業務語言設計模型。

我在做一個線上課程平台，核心業務如下：
- 學生購買課程（單堂 or 訂閱制）
- 講師上傳影片、作業
- 學生完成作業，講師批改
- 結業後發放數位證書

請用 /domain-modeling 設計 Prisma schema。

3. /typescript-patterns — TypeScript 進階模式

Matt Pocock 是 TypeScript 大師，這個 skill 整合了他多年的 TypeScript 最佳實踐：

  • Type inference 技巧（讓 TypeScript 自動推斷，減少手動標注）
  • Generic constraints 正確用法
  • Discriminated unions（比 enum 更安全）
  • Template literal types 實戰範例
  • Conditional types 設計模式

4. /error-handling — 錯誤處理標準化

統一 TypeScript 專案的錯誤處理方式，包含 Result 模式、Never Error Pattern、Type-safe error propagation。

5. /testing-strategy — 測試策略

不只是「怎麼寫測試」，而是「什麼值得測試、什麼不值得」的完整決策框架。整合 Vitest、Testing Library、Playwright。

常見問題 Q&A

Q1：Matt Pocock Skills 和 Cursor Rules 可以同時用嗎？

可以。Matt Pocock Skills 的 .cursorrules 設計就是讓你在 Cursor 內用的。安裝後，.cursorrules 會包含 progressive disclosure 邏輯，讓 Cursor 按需載入 skills。

Q2：只用 TypeScript 才有用嗎？

不是。雖然 Matt Pocock 是 TypeScript 大師，但 skills 裡的 /codebase-design、/domain-modeling、/error-handling 都是語言無關的。JavaScript、Python 開發者同樣受益。

Q3：v1.0 向下相容嗎？

完全相容。如果你之前用的是 mattpocock/skills 的舊版，直接 git pull 升級即可。新增的 skills（/codebase-design、/domain-modeling）不影響舊的使用方式。

Q4：和 Addy Osmani Agent Skills 衝突嗎？

不衝突。兩套可以共存於同一個 .skills/ 目錄，建議把 Addy Osmani 的通用 skills 保留，用 Matt Pocock Skills 補強 TypeScript 相關部分。

Q5：Token 節省的 63% 是絕對數字嗎？

這是 Matt Pocock 團隊的內部測試平均值，實際節省幅度取決於你使用的 skills 數量。如果你的專案只用 3-4 個 skills，節省幅度可能是 40-50%；如果你安裝了 15+ 個 skills，節省效果會更接近 63%。

建立自訂 skills 的關鍵是：Summary 段落要精簡（AI 第一層只看 Summary），詳細內容放在分隔線後面。
