REA 是什麼？GitHub Trending #1 的逆向工程 Agent

REA（Reverse Engineer Agent） 是由 morluto 開發的開源 AI agent，專門用於逆向工程 Android APK、IoT 韌體、二進位檔案。它在 2026 年 10 月 7 日登上 GitHub Trending #1，單日新增 +4,666 stars，累積 14,540+ stars，成為逆向工程社群最熱門的 AI 工具。

REA 的核心特色是「零 API 費用」— 它不依賴 OpenAI/Anthropic 等付費 API，而是使用 本地 LLM（Ollama/LM Studio） + 開源逆向工具鏈（Ghidra/Radare2/apktool/Frida），讓逆向工程師在不支付 AI API 費用的前提下，獲得「AI 輔助逆向分析」能力。

為什麼 REA 爆紅？

2026 年逆向工程社群的痛點是：傳統工具（IDA Pro/Ghidra）學習曲線陡峭，AI 輔助工具（如 ChatGPT Code Interpreter）又需要付費 API 且無法處理 binary 檔案。REA 填補了這個空白，提供「本地 LLM + 專業逆向工具鏈」的整合方案，讓新手也能快速上手 APK/韌體逆向。

核心功能：APK/韌體/Binary 逆向工程

REA 支援以下逆向工程任務：

1. Android APK 逆向工程

  • APK 解包：自動執行 apktool d 解包 APK，提取 AndroidManifest.xml、資源檔、smali 代碼
  • 權限分析：分析 <uses-permission> 標籤，識別 high-risk permissions（例如 READ_CONTACTS / SEND_SMS）
  • Activity/Service 分析：列出所有 Activity、Service、BroadcastReceiver，識別潛在攻擊面
  • 惡意行為檢測：識別混淆代碼、加殼、root 檢測、反調試等常見惡意技術

2. IoT 韌體逆向工程

  • 韌體提取：從 .bin / .img 檔案提取檔案系統（使用 binwalk）
  • Hardcoded Credentials 搜尋：自動掃描 admin / root / password 等 hardcoded 帳密
  • 網路服務分析：識別開放的 telnet/ssh/http 服務，評估安全風險
  • 加密演算法識別：識別 AES/DES/RSA 等加密演算法的實作

3. 二進位檔案逆向工程

  • 反組譯：使用 Ghidra/Radare2 自動反組譯 ELF/PE/Mach-O 檔案
  • 函數呼叫圖：生成函數呼叫關係圖，識別關鍵函數（例如 encrypt() / verify_license()）
  • 字串分析：提取所有可讀字串，識別 API endpoints / hardcoded keys / debug messages
  • 動態追蹤：整合 Frida，動態追蹤函數執行流程

技術架構：MCP Server + CLI 雙模式

REA 提供兩種使用模式：

1. MCP Server 模式（推薦）

MCP（Model Context Protocol） 是 Anthropic 推出的 AI agent 標準協議，REA 實作了完整的 MCP Server，可以無縫整合到：

  • Claude Code：在 VSCode 中直接調用 REA 分析 APK/binary
  • OpenClaw：在 Telegram/LINE bot 中調用 REA 逆向工程服務
  • Codex / Pi：任何支援 MCP 的 coding agent

MCP Server 的優勢是「agent 之間可以互相調用」— 例如 Claude Code 在分析 APK 時，可以自動調用 REA 的 analyze_apk tool，無需手動複製貼上結果。

2. CLI 模式

REA 也提供傳統的 CLI 介面，適合「一次性逆向任務」或「整合到 CI/CD pipeline」的場景：

# 分析 APK
rea analyze-apk app.apk

# 分析韌體
rea analyze-firmware router.bin

# 分析 ELF binary
rea analyze-binary /usr/bin/suspicious_app

本地 LLM 支援

REA 預設使用 Ollama 作為本地 LLM backend，支援的模型包括：

  • Llama 3.1 70B（推薦）：最佳逆向分析品質
  • Mistral Large 4（23B active）：速度與品質平衡
  • Qwen 3.8 Flash（14B active）：速度最快，適合快速掃描
  • DeepSeek Coder V4：最強 code understanding，適合複雜 binary

關鍵優勢：所有推論在本地執行，不會外洩逆向工程的敏感資料（例如客戶的 APK 檔案、內部韌體）。

安裝教學：從零開始設定 REA

前置需求

  • 作業系統：Linux / macOS（推薦）/ Windows WSL2
  • Python：3.10+
  • Ollama：本地 LLM runtime（ollama.com）
  • 逆向工具：apktool / Ghidra / radare2 / binwalk / Frida（REA 會自動安裝）

Step 1：安裝 Ollama + 下載模型

# macOS / Linux
curl -fsSL https://ollama.com/install.sh | sh

# 下載 Llama 3.1 70B（推薦，需要 48GB RAM）
ollama pull llama3.1:70b

# 或下載 Mistral Large 4（23B active，需要 24GB RAM）
ollama pull mistral-large-4

# 或下載 Qwen 3.8 Flash（14B active，需要 16GB RAM，速度最快）
ollama pull qwen3.8-flash

Step 2：Clone REA Repository

git clone https://github.com/morluto/rea.git
cd rea
pip install -r requirements.txt

Step 3：安裝逆向工具鏈

# REA 提供一鍵安裝腳本（Linux/macOS）
./scripts/install-tools.sh

# 或手動安裝（Ubuntu/Debian）
sudo apt-get install apktool radare2 binwalk ghidra

# macOS
brew install apktool radare2 binwalk ghidra

Step 4：啟動 MCP Server（選配）

# 啟動 REA MCP Server（預設 port 8765）
rea serve --port 8765 --model llama3.1:70b

# 測試 MCP Server
curl http://localhost:8765/mcp/tools

Step 5：第一次逆向分析

# 下載範例 APK
wget https://example.com/sample.apk

# CLI 模式分析
rea analyze-apk sample.apk --output report.json

# MCP 模式分析（在 Claude Code 中執行）
# 1. 開啟 Claude Code
# 2. 輸入：@rea analyze sample.apk
# 3. REA 自動分析並返回報告

硬體需求建議

最低配置：16GB RAM + Qwen 3.8 Flash（速度快但分析品質中等）
推薦配置：48GB RAM + Llama 3.1 70B（最佳分析品質）

實戰案例：Android APK 逆向工程

以下是使用 REA 分析一個「可疑的 Android 工具 APK」的完整流程。

案例背景

客戶收到一個「手電筒 App」（flashlight.apk），懷疑它偷偷收集用戶資料並上傳到遠端伺服器。我們使用 REA 進行逆向分析。

Step 1：基本資訊提取

rea analyze-apk flashlight.apk --verbose

# 輸出摘要
[+] Package: com.example.flashlight
[+] Version: 1.2.3
[+] Min SDK: 21 (Android 5.0)
[+] Target SDK: 33 (Android 13)
[!] HIGH-RISK permissions detected:
    - READ_CONTACTS (讀取聯絡人)
    - ACCESS_FINE_LOCATION (精確定位)
    - SEND_SMS (發送簡訊)
    - INTERNET (網路存取)

分析：一個「手電筒 App」不應該需要讀取聯絡人、定位、發送簡訊的權限 — 這是明顯的惡意跡象。

Step 2：Activity 與 Service 分析

[+] Activities:
    - MainActivity (正常的主畫面)
    - SettingsActivity (設定頁)
    - HiddenActivity (未在 Launcher 顯示！可疑)

[+] Services:
    - FlashlightService (正常的手電筒服務)
    - DataUploadService (可疑！持續背景運行)

[+] Broadcast Receivers:
    - BootReceiver (開機自動啟動！可疑)

分析：HiddenActivity、DataUploadService、BootReceiver 都是惡意 App 常見的元件。

Step 3：網路流量分析

[+] Network endpoints detected:
    - https://api.flashlight.com/v1/upload (正常 API)
    - http://203.0.113.42:8080/collect (可疑！非 HTTPS + 陌生 IP)

[+] Hardcoded API keys:
    - API_KEY = "sk_live_abc123xyz..." (外洩的 API key！)

分析：http://203.0.113.42:8080/collect 是一個未加密的 HTTP endpoint，可能用來上傳竊取的資料。

Step 4：Smali 代碼分析（AI 輔助）

REA 使用本地 LLM 分析 smali 代碼，自動識別惡意行為：

[AI Analysis] DataUploadService.smali:
- Line 142: 讀取聯絡人資料庫 (ContactsContract.Contacts.CONTENT_URI)
- Line 158: 讀取 GPS 座標 (LocationManager.getLastKnownLocation)
- Line 201: 使用 HttpURLConnection 發送 POST 請求到 203.0.113.42:8080
- Line 215: 無加密直接傳輸 (未使用 HTTPS/TLS)

[VERDICT] 高度可疑：此 Service 收集用戶聯絡人與定位，未加密上傳到遠端伺服器。

最終結論

REA 自動生成報告：

Malware Confidence: 95%

此 APK 包含明顯的惡意行為：收集聯絡人、定位資料，透過未加密的 HTTP 上傳到遠端伺服器 203.0.113.42:8080。建議立即刪除並通報 Google Play Protect。

MCP Server 整合：Claude Code / OpenClaw

在 Claude Code 中使用 REA

Claude Code 原生支援 MCP Server，整合步驟：

  1. 啟動 REA MCP Server：rea serve --port 8765
  2. 在 Claude Code 中新增 MCP Server： 
    # settings.json
{
  "mcp.servers": [
    {
      "name": "rea",
      "url": "http://localhost:8765",
      "tools": ["analyze_apk", "analyze_firmware", "analyze_binary"]
    }
  ]
}
  3. 在 Claude Code 中輸入：@rea analyze sample.apk
  4. Claude Code 自動調用 REA，返回逆向分析報告

在 OpenClaw 中使用 REA

OpenClaw 是自架 AI assistant，支援 MCP Server 整合：

# ~/.config/openclaw/config.yaml
mcp:
  servers:
    - name: rea
      url: http://localhost:8765
      tools:
        - analyze_apk
        - analyze_firmware

整合後，在 Telegram/LINE 中直接上傳 APK 檔案，OpenClaw 自動調用 REA 分析：
