SandboxAQ Switch 是什麼？

想像一下：你的開發團隊在 Slack 上討論 Bug，然後直接 @claude 叫 AI 把問題分析結果貼到同一個頻道——不需要開瀏覽器、不需要切換工具、不需要複製貼上。這就是 SandboxAQ Switch 解決的核心痛點。

SandboxAQ Switch 是一個開源的 AI Agent 協作平台適配器，讓任何 AI Agent（Claude Code、LangChain Agent、Google ADK、OpenAI Assistants API）在 10 分鐘內部署進 Slack、Microsoft Teams、Discord 或 Telegram，以原生 Bot 的形式與團隊互動。

💡 一句話理解 Switch

Switch 是 AI Agent 的 「插座適配器」——你的 AI Agent 插上去，自動適配 Slack / Teams / Discord / Telegram 的溝通協議，團隊成員直接在慣用的通訊工具裡跟 AI 互動。

SandboxAQ 是誰？這個背景很重要

SandboxAQ 成立於 2022 年，由 Google / Alphabet 內部孵化獨立，主要專注於量子計算與 AI 安全應用。開發 Switch 的是其旗下的 Flint AI 部門，專注於企業 AI 部署加速。

這個背景意味著：Switch 不是小型創業公司的實驗性工具，背後有 Google 工程文化加持，企業級可靠性相對有保障。PR Newswire 官方公告確認這不是社群 fork 而是 SandboxAQ 的正式開源產品。

完整安裝教學：Slack 範例（Step by Step）

前置需求

環境確認

  • Python 3.10+ 或 Node.js 20+（Switch 同時支援兩種語言）
  • Slack Workspace 管理員權限（建立 App 需要）
  • AI Agent API Key（Anthropic / OpenAI / Google 等）
  • 可公開訪問的 HTTPS 端點（或使用 ngrok 測試）
Step 1

Clone 並安裝 Switch

git clone https://github.com/sandboxaq/switch
cd switch
pip install -r requirements.txt   # Python 版本
# 或
npm install                       # TypeScript 版本
Step 2

在 Slack 建立 Bot App

前往 api.slack.com/apps，點選「Create New App」→「From Manifest」，貼上 Switch 提供的 manifest 範本：

# switch/templates/slack-manifest.yaml
display_information:
  name: "Switch AI Agent"
  description: "AI Agent powered by SandboxAQ Switch"
features:
  app_home:
    home_tab_enabled: false
  bot_user:
    display_name: "AI Assistant"
    always_online: true
oauth_config:
  scopes:
    bot:
      - channels:history
      - channels:read
      - chat:write
      - im:history
      - im:write
      - app_mentions:read
settings:
  event_subscriptions:
    bot_events:
      - app_mention
      - message.im
  interactivity:
    is_enabled: false
  org_deploy_enabled: false

建立後取得：Bot Token（xoxb-...） 和 Signing Secret。

Step 3

設定環境變數（.env）

# .env
SWITCH_PLATFORM=slack
SLACK_BOT_TOKEN=xoxb-xxxxxxxxxxxx
SLACK_SIGNING_SECRET=xxxxxxxxxxxx

# AI Agent 設定（以 Claude 為例）
AGENT_TYPE=claude
ANTHROPIC_API_KEY=sk-ant-xxxxxxxxx
AGENT_MODEL=claude-sonnet-4-5

# 可選：自訂 system prompt
AGENT_SYSTEM_PROMPT="你是一個 AI 開發助手，協助台灣工程師解決技術問題。請用繁體中文回答。"
Step 4

啟動 Switch 服務

# 本機測試（使用 ngrok 建立公開 HTTPS）
ngrok http 3000  # 在另一個終端機執行

# 啟動 Switch
python main.py  # 或 npm start

# 輸出應看到：
# ✅ Switch running on port 3000
# ✅ Slack platform adapter loaded
# ✅ Claude agent initialized

把 ngrok 給你的 HTTPS URL + /slack/events 填入 Slack App 的 Event Subscriptions → Request URL 欄位。

Step 5

安裝 App 到 Workspace 並測試

在 Slack App 管理頁面點「Install to Workspace」，確認授權後，在任意頻道 @Switch AI Agent：

@Switch AI Agent 請分析以下 Python code 有什麼問題：
def get_user(id):
    return db.query(f"SELECT * FROM users WHERE id={id}")

如果設定正確，Bot 會在 30 秒內回應 SQL Injection 風險分析。

Microsoft Teams 部署教學

讓 Claude Code Agent 常駐 Slack 頻道：進階設定

Switch 支援 Claude Code 的工具調用（Tool Use）功能，讓它在 Slack 頻道裡也能執行完整的 agent 任務。以下是一個讓 Claude Code 處理 GitHub PR Review 的設定：

# switch.config.yaml（進階設定）
agent:
  type: claude
  model: claude-sonnet-4-5
  system_prompt: |
    你是 AutoDev 團隊的 AI 開發助手。
    當收到 PR Review 請求時，分析程式碼品質、安全性和效能。
    用繁體中文回覆，格式化輸出包含：
    1. 問題摘要（1-3 個重點）
    2. 具體建議（附 code snippet）
    3. 嚴重程度（Critical / Major / Minor）

  tools:
    - file_read        # 讀取檔案
    - web_search       # 搜尋技術文檔
    - github_pr_fetch  # 取得 PR 差異

slack:
  allowed_channels:
    - "#engineering"
    - "#code-review"
  mention_required: true    # 需要 @mention 才觸發
  thread_replies: true      # 回覆在 thread 而非頻道主流

rate_limiting:
  requests_per_user_per_hour: 20
  max_tokens_per_response: 2000

場景 1：工程團隊 Slack — Claude Code 常駐 PR Review

在 #code-review 頻道設定 Switch，讓 Claude Code 自動回應 PR Review 請求。開發者只需貼上 GitHub PR 連結並 @AI Review，10 秒內收到中文分析報告。

省時估算：5 人工程團隊，每週 20 個 PR，每個節省 5 分鐘 = 每週省 100 分鐘人力。

場景 2：電商公司 Teams — 庫存與訂單問答

將 LangChain Agent（已連接公司 ERP API）透過 Switch 部署進 Teams。業務人員直接在 Teams 問：「今天庫存還有幾件 SKU-123？」——不用進 ERP 後台，也不需要 IT 人員協助。

場景 3：新創公司 Discord — 全棧技術問答機器人

Discord 是台灣工程師社群常用平台。將 Google ADK Agent（連接技術文檔向量資料庫）透過 Switch 掛到 #dev-help 頻道，Junior 工程師可以直接在 Discord 問框架問題，不佔用 Senior 時間。

場景 4：遠端工作 Telegram 群組 — 多語言工作助手

台灣公司與海外合作夥伴常用 Telegram。Switch 可以讓 Claude 以多語言 Agent 身份在 Telegram 群組中運作，自動翻譯會議摘要、回答規格問題，讓台灣端與海外合作夥伴溝通更順暢。

Apache 2.0 + Commons Clause 授權說明

Switch 採用 Apache 2.0 + Commons Clause 雙重授權，這是近年來開源工具常用的「開源但不可商業競爭」模式：

  • ✅ 可以：用於自家公司內部部署（商業使用，但是自用）
  • ✅ 可以：修改源碼、整合進自家產品
  • ✅ 可以：為客戶部署（顧問/SI 廠商）
  • ❌ 不可以：把 Switch 包裝後以服務形式販售（即不能做「Switch as a Service」直接賺錢）

⚠️ 對台灣 SI 廠商的注意

如果你的公司是系統整合商（SI），幫客戶「部署 Switch 並收服務費」通常是允許的（Commons Clause 主要限制的是直接銷售 Switch 本身的使用授權）。但建議在大型合約前諮詢法律意見，因為「Commons Clause」的邊界在法律上仍有討論空間。

常見問題 FAQ

Q：Switch 和 Botpress / ManyChat 有什麼不同？
A：Botpress / ManyChat 是 聊天機器人平台，你要在平台上設計對話流程。Switch 是 AI Agent 適配器，你帶著已有的 AI Agent（Claude Code / LangChain Agent），Switch 負責讓它和 Slack/Teams 溝通。前者適合「設計對話流程」，後者適合「把現成 AI Agent 放進通訊工具」。
Q：部署在 DigitalOcean 上安全嗎？對話內容會被看到嗎？
A：Switch 本身不存儲對話內容（除非你額外設定記憶體插件）。訊息路徑是：Slack → Switch（你的 VPS）→ Claude API。Switch VPS 是你自己的機器，資安責任在你；Claude API 的對話則依 Anthropic 隱私政策處理。Enterprise 使用者可開啟 Zero Data Retention（不保留對話紀錄）。
Q：10 分鐘真的夠部署好嗎？
A：本機測試 + ngrok 的話確實 10 分鐘可以看到第一個回應。但是「生產就緒」部署（VPS + HTTPS 正式域名 + 監控 + rate limiting）大概需要 1-2 小時。對有 Docker 和 Linux 經驗的工程師來說，本文的 5 步驟完全可行。
Q：哪些 AI Agent 類型最適合用 Switch？
A：最適合的是「有工具調用能力的對話式 Agent」——例如 Claude Code（可讀檔案）、LangChain Agent（可查資料庫）、Google ADK Agent（可搜尋網路）。純文字 LLM 也可以接，但沒有工具調用就少了大部分實用性。
Q：LINE 個人版何時支援？
A：根據 GitHub Issues 討論，LINE Messaging API 的 Webhook 架構和 Slack/Teams 不同，需要獨立開發適配器。目前優先順序是 LINE Works（企業版）而非個人版 LINE。如果你有強烈需求可以到 GitHub 提 Issue 投票。
Q：Systeme.io 可以和 Switch 整合嗎？
A：Systeme.io 是行銷漏斗 / 課程平台，目前 Switch 不提供直接整合。但你可以用 Webhook 把 Systeme.io 的新用戶事件傳到 Switch，讓 AI Agent 在 Slack/Teams 收到通知並自動處理後續任務（例如發送歡迎郵件的指令）。
