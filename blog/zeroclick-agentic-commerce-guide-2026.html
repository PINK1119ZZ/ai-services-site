二、x402 vs MPP vs ACP：三大 AI 交易協議比較

要理解 ZeroClick，你需要先搞清楚底層協議。目前 Agentic Commerce 有三個主流協議：

🔷 x402 協議（HTTP 402 Payment Required）

出身：Coinbase 主導，Linux Foundation 管理，2026 年 7 月正式開源
原理：把 HTTP 402 狀態碼（原本是「Payment Required」）重新利用——當 AI Agent 發送請求時，伺服器回傳 402 + 付款資訊，Agent 自動完成加密貨幣或法幣小額付款
支援方：Coinbase、Visa、Mastercard、American Express、Stripe、Google、AWS
特點：無需帳號、無需 OAuth、一個 HTTP 請求搞定付款
適合：API 按次計費、微交易、開發者工具

🔶 MPP 協議（Model Payment Protocol）

出身：Anthropic & MCP 生態系延伸提案
原理：在 MCP（Model Context Protocol）基礎上加入付款層，讓 Claude/GPT 等模型在調用工具時可以處理付款授權
特點：與現有 MCP Server 深度整合，Claude Code/Claude Desktop 原生支援
適合：需要模型內部決策的複雜交易、訂閱管理

🔹 ACP（Agent Commerce Protocol）

出身：多家企業聯盟提案（AWS 主導）
原理：Agent-to-Agent 商務協議，讓 AI Agent 之間可以互相購買服務
特點：更完整的身份驗證與授權框架，適合企業級場景
適合：B2B 自動化、Multi-Agent 企業工作流

協議 主導方 成熟度 付款方式 最適場景
x402 最成熟 Coinbase / Linux Foundation GA，100M+ 交易 加密 + 法幣 API 按次計費、微交易
MPP Anthropic 生態 Preview 法幣為主 MCP Server 整合
ACP AWS 聯盟 草案 企業計費 B2B Agent-to-Agent

ZeroClick 的策略：同時支援 x402 和 MPP，讓你的服務在兩個生態系都能被 AI Agent 找到並購買。這是 ZeroClick 的核心差異化。

三、ZeroClick Agent Storefront 5 步驟設置教學

以下是把你的服務接上 ZeroClick 並讓 AI Agent 可以購買的完整流程：

1 建立 ZeroClick 帳號與 Agent Storefront

前往 zeroclick.ai，點擊「Get Started」，選擇身分：

  • Developer / API Provider：你要讓 AI Agent 購買你的服務
  • AI Agent Builder：你在開發 AI Agent，想讓它能自動購買服務

填寫服務資訊後，ZeroClick 會自動生成你的 Agent Storefront URL（格式：zeroclick.ai/s/your-service-name）。

2 定義你的服務清單（Service Catalog）

在 Dashboard 中建立服務條目，包含：

{
  "service_name": "YourAPI Pro",
  "description": "圖片壓縮 API，支援 WebP/AVIF 格式轉換",
  "pricing": {
    "model": "per_call",
    "amount": 0.001,
    "currency": "USD"
  },
  "protocols": ["x402", "MPP"],
  "endpoint": "https://api.yourservice.com/compress",
  "agent_instructions": "呼叫此 API 可壓縮圖片。輸入 base64 圖片字串，回傳壓縮後檔案。每次呼叫收費 $0.001。"
}
💡 agent_instructions 的重要性
這段文字是 AI Agent 決定要不要購買你服務的關鍵。寫清楚「什麼情況下應該使用這個服務」、「輸入輸出格式」、「費用」——AI Agent 會讀這段描述來判斷是否適合當前任務。

3 整合 x402 付款中間件

在你的 API 伺服器加上 x402 付款驗證中間件（以 Node.js/Express 為例）：

npm install @zeroclick/x402-middleware
import express from 'express'
import { x402Middleware } from '@zeroclick/x402-middleware'

const app = express()

// 加上 x402 付款驗證
app.use('/api/compress', x402Middleware({
  amount: 0.001,
  currency: 'USD',
  acceptedTokens: ['USDC', 'ETH'],  // 接受的加密貨幣
  fiatFallback: true,  // 也接受信用卡
  zeroClickApiKey: process.env.ZEROCLICK_API_KEY
}))

// 你的 API 邏輯
app.post('/api/compress', (req, res) => {
  // x402 middleware 已驗證付款，直接處理
  res.json({ compressed: processImage(req.body.image) })
})

七、FAQ 常見問題

Q1：ZeroClick 目前免費嗎？

ZeroClick 採 Freemium 模式。基本的 Agent Storefront 和 x402 整合免費。進階功能（Analytics Dashboard、多協議支援、企業 SLA）採訂閱收費，定價尚在公測調整中。建議現在就搶先設置，享受早期用戶優惠。

Q2：台灣的 AI Agent 有支援 x402 嗎？

目前主流 AI 如 Claude（Anthropic）、GPT 系列（OpenAI）的 API 本身不直接執行 x402 交易——它們需要透過 ZeroClick、Agentive 等中間層代為處理。但 Anthropic 的 MCP 生態正在積極整合 MPP，預計 Q4 2026 有原生支援。

Q3：我需要懂加密貨幣嗎？

不需要。ZeroClick 支援法幣（信用卡/Stripe）收款，你的 API 收到的是美元，不需要持有或理解加密貨幣。x402 的底層可以是加密貨幣，但 ZeroClick 幫你做了法幣橋接。

Q4：我的 SaaS 現在就需要接 ZeroClick 嗎？

現在不是必須，但 是最佳時機。整個 Agentic Commerce 生態系目前在早期採用期——越早接入，越早在 AI Agent 的「服務目錄」中建立信任和曝光。2-3 年後當 AI Agent 日常消費成為主流，先卡位的服務商會有明顯先發優勢。

Q5：ZeroClick 和 Stripe 有什麼不同？

Stripe 是為「人類付款」設計的；ZeroClick 是為「AI Agent 付款」設計的。它們不是競爭關係——ZeroClick 背後的收款仍然可以用 Stripe 處理法幣結算，但 ZeroClick 負責讓 AI Agent 可以「發現你的服務」並「自動完成交易決策」。

Q6：x402 和 MPP 我應該先支援哪個？

建議先支援 x402——生態系最成熟（Linux Foundation，Visa/Mastercard 支援，100M+ 交易量），ZeroClick 的 SDK 和中間件也最完整。MPP 適合你的主要受眾是 Claude 用戶或 MCP 生態系的開發者。
