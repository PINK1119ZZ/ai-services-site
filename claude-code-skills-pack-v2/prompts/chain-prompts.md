# Chain Prompts — 多輪對話串接模板
**Claude Code Skills Pack v2.0 · prompts/chain-prompts.md**

---

## 什麼是 Chain Prompt？

複雜任務不適合用一個 prompt 解決。Chain Prompt 把任務拆成多個步驟，每輪只做一件事，利用 Claude 的對話記憶串接起來。好處是：每步都可以確認正確性再繼續，避免後期才發現前面跑偏。

---

## Chain 01：完整功能開發流程

適合開發一個新功能（從需求到測試）。

**輪次 1：需求分析**
```
我要開發以下功能：[功能描述]
現有的程式碼架構：[貼入相關程式碼或目錄結構]

請幫我分析：
1. 這個功能需要哪些技術元件？
2. 有哪些邊界情況需要處理？
3. 推薦的實作方案（附簡短理由）
暫時不要寫程式碼，等我確認後再進行。
```

**輪次 2：確認後生成介面（Interface / Type）**
```
上面的分析看起來正確。請先生成：
1. TypeScript 介面定義 / Function signatures
2. 資料庫 schema 變更（若需要）
暫時不要寫實作邏輯。
```

**輪次 3：生成測試**
```
介面定義看起來好了。請根據上面的介面，先寫完整的測試（Jest），涵蓋所有 edge case。
實作還不存在，所以測試現在應該全部 fail。
```

**輪次 4：實作**
```
測試看起來完整了。請寫讓測試通過的實作程式碼。
```

**輪次 5：審查與優化**
```
請審查上面實作的：
1. 安全性（有沒有注入風險或未驗證輸入）
2. 效能（有沒有明顯的 N+1 或不必要的重複計算）
3. 錯誤處理（有沒有漏掉的 exception）
```

## Chain 02：系統性 Debug 流程

適合難以定位的複雜 bug。

**輪次 1：症狀描述**
```
我有一個 bug，先讓我描述症狀：
[詳細描述預期行為、實際行為、出現條件、錯誤訊息]
相關程式碼：[貼入]
請列出 3-5 個可能原因，依可能性排序，先不要給解法。
```

**輪次 2：驗證最可能的原因**
```
[選擇你覺得最可能的假設]
請告訴我：如何用最少的步驟驗證這個假設是否正確？
```

**輪次 3（確認後）：修復方案**
```
驗證結果：[說明你驗證到了什麼]
確認是 [原因] 造成的問題。請給出修復方案和對應的測試。
```

## Chain 03：程式碼漸進重構

適合大型重構，確保每步可以獨立 commit。

**輪次 1：評估技術債**
```
請評估以下程式碼的技術債，用優先序排列（高/中/低），不要開始重構：
[貼入程式碼]
```

**輪次 2：第一輪重構（高優先）**
```
請只處理上面 HIGH priority 的項目，保持 MEDIUM 和 LOW 不動：
這樣我可以在一個 PR 處理最重要的問題。
```

**輪次 3：確認後繼續 MEDIUM**
```
第一輪重構看起來正確，請繼續處理 MEDIUM priority 的項目：
```

## Chain 04：文件補全流程

適合為沒有文件的遺留程式碼補文件。

**輪次 1：理解程式碼**
```
請閱讀以下程式碼，用 3 句話說明它做什麼，以及有哪些隱藏的假設（implicit assumptions）：
[貼入程式碼]
```

**輪次 2：生成 JSDoc**
```
你的理解正確。請生成完整的 JSDoc 注釋，重點說明「為什麼」和邊界情況，不只是「做什麼」：
```

**輪次 3：生成 README 段落**
```
請根據你對這段程式碼的理解，生成一個 README 段落，包含：使用方式、範例、已知限制。
目標讀者：[例如：接手這個模組的新工程師]
```

## 通用 Chain 技巧

**暫停技巧**（防止 Claude 跑太快）：
```
請先做步驟 1，完成後等我確認再繼續步驟 2。
```

**確認理解**（重要任務前）：
```
在開始之前，請用你自己的話重述這個任務的目標和限制條件，確保我們對齊了再開始。
```

**回滾指令**（若某步不滿意）：
```
上一步的方向不對，請退回到步驟 [X] 的結果，改用 [不同方法] 繼續。
```
