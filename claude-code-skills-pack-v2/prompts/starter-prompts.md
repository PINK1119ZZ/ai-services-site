## 🔍 程式碼審查類（1-8）

**01. 快速整體審查**
```
請審查以下程式碼，優先找出安全漏洞和邏輯錯誤，次要是可讀性建議：
[貼入程式碼]
```

**02. PR 審查模式**
```
這個 PR 的目的是：[PR 描述]
以下是 diff：
[貼入 git diff]
請用 GitHub comment 格式給審查意見，每個問題附檔案名和行號。
```

**03. 只看安全性**
```
只做安全性審查，找出 OWASP Top 10 相關風險：
[貼入程式碼]
```

**04. 命名和可讀性**
```
請審查以下程式碼的命名和可讀性，不需要看功能邏輯：
[貼入程式碼]
用「改前 → 改後」格式給建議。
```

**05. 找 N+1 Query**
```
請找出以下程式碼中所有 N+1 查詢問題，並給出使用 JOIN 或 Eager Loading 的修復方案：
[貼入程式碼]
資料表大小：[說明資料量]
```

**06. 審查錯誤處理**
```
請只審查這段程式碼的錯誤處理，找出所有可能的 unhandled exception 和遺失的 error case：
[貼入程式碼]
```

**07. 比較兩個實作**
```
以下是同一功能的兩個實作，請比較優缺點並推薦哪個：
實作 A：[程式碼]
實作 B：[程式碼]
情境：[說明使用場景和限制條件]
```

**08. 接手陌生程式碼**
```
我剛接手這段程式碼，沒有任何文件。請幫我：
1. 用 3 句話說明這段程式碼做什麼
2. 找出最容易出錯的地方
3. 如果我要修改它，最需要注意什麼？
[貼入程式碼]
```

## 🔧 重構類（9-14）

**09. 拆分長函數**
```
這個函數太長，請把它拆成職責單一的子函數：
[貼入程式碼]
限制：不能改變 function signature（其他地方有依賴）。
```

**10. 消除重複**
```
以下幾段程式碼有重複邏輯，請找出並抽取共用函數（但不要過度抽象）：
[貼入多段程式碼]
```

**11. Promise → async/await**
```
請將以下 Promise chain 改成 async/await 語法，保持相同行為：
[貼入程式碼]
```

**12. 改善型別安全（TypeScript）**
```
以下 TypeScript 程式碼用了很多 any，請在不改變行為的前提下，盡量加上正確的型別：
[貼入程式碼]
```

**13. 移除全域狀態**
```
這段程式碼依賴全域變數，請重構成依靠函數參數傳遞狀態（不用全域）：
[貼入程式碼]
```

**14. Class → 函數式**
```
請將這個 Class 重構成函數和純函數的組合（functional style），保持相同 API：
[貼入程式碼]
```

## 🧪 測試類（15-19）

**15. 補測試（最小覆蓋）**
```
請為以下函數生成最少的測試，達到 80% 覆蓋率（Jest）：
[貼入程式碼]
框架：[Jest / Vitest / Pytest / 其他]
```

**16. TDD 模板**
```
我要實作：[功能描述]
請先幫我寫完整測試（[框架]），涵蓋所有 edge case，我再根據測試寫實作。
```

**17. Mock 外部依賴**
```
這個函數依賴外部 API，請幫我生成有效的 Mock，讓我可以在無網路環境下測試：
[貼入程式碼]
```

**18. 測試命名改善**
```
以下測試的命名不清楚，請改成「描述行為而非實作」的命名方式：
[貼入測試程式碼]
```

**19. 找測試盲點**
```
以下是現有的測試，請分析有哪些情境沒有被覆蓋到（特別是 edge case 和 error path）：
[貼入測試程式碼]
對應的實作：
[貼入實作程式碼]
```

## 🐛 Debug 類（20-24）

**20. 解釋錯誤訊息**
```
請解釋以下錯誤訊息的意思，以及最可能的根本原因：
錯誤：[貼入錯誤訊息]
相關程式碼：[貼入程式碼]
```

**21. 偶發性 bug**
```
這個 bug 只偶爾出現，頻率約 [X%]，在高並發時更常見。
症狀：[說明]
程式碼：[貼入]
請提出 3 個最可能的原因和驗證方法。
```

**22. 二分法定位**
```
以下程式碼有 bug，請告訴我在哪裡加 console.log 可以最快縮小問題範圍：
[貼入程式碼]
症狀：[說明預期 vs 實際行為]
```

**23. 解讀 Stack Trace**
```
請分析以下 stack trace，指出根本原因和最可能需要修改的位置：
[貼入完整 stack trace]
```

**24. 非同步 bug**
```
這段 async/await 程式碼行為不符預期，請找出問題：
[貼入程式碼]
預期：[說明]
實際：[說明]
```

## ⚡ 效能類（25-27）

**25. SQL 慢查詢優化**
```
以下 SQL 查詢在資料量大時很慢（約 [X] 秒），請分析原因並優化：
[貼入 SQL]
資料量：[說明]
現有 index：[說明或貼入 CREATE INDEX]
```

**26. React 渲染優化**
```
這個 React 元件在列表有 [X] 筆資料時會卡頓，請找出不必要的重新渲染並優化：
[貼入元件程式碼]
```

**27. 非同步並行化**
```
以下程式碼是串行執行，其中哪些可以改成並行（Promise.all）？請改寫並說明預期加速幅度：
[貼入程式碼]
```

## 🤖 Agent / 自動化類（28-30）

**28. 分析程式碼庫結構**
```
請分析這個專案的目錄結構，說明各目錄的職責，以及新功能應該放在哪裡：
[貼入 tree 輸出或目錄結構]
```

**29. 生成實作計畫**
```
我要新增以下功能：[功能描述]
現有程式碼結構：[貼入相關檔案或目錄樹]
請生成一個分步驟的實作計畫，讓我可以分成多個獨立的 PR 執行。
```

**30. 程式碼說明（給非工程師）**
```
請用非技術人員能理解的語言解釋以下程式碼在做什麼（不超過 5 句話）：
[貼入程式碼]
受眾：[例如：產品經理 / 客戶 / 主管]
```
